# AI Agent Working Rules

## 📌 Описание проекта

Это Python сервис, который агрегирует данные из внешних API сервисов.

Основная задача:
- получать данные из внешних источников
- нормализовать данные
- сохранять агрегированные результаты

---

## 🧱 Структура проекта

marketplace_analysis/ Хранятся все методы связанные с аналитиков маркетплейсов (Ozon, Wildberries, Yandex Market)

platform_analysis/
    
Хранится вся логика для аналитики платформы

data_transfer/
    
Модуль для переезда из одной бд в другую, тебе он не нужен, не используй его


main.py - Основной скрипт, в котором вызываются все другие методы для ежедневного обновления данных на сервере

config.py - Все необходимые ключи и права доступа находятся тут. Также тут логгер инициализируется

---

## 🧑‍💻 Общие правила разработки

AI агент должен:

- Следовать существующему стилю кода
- Использовать уже существующие паттерны проекта
- Не рефакторить чужой код без необходимости
- Делать минимальные изменения для решения задачи
- Не добавлять новые зависимости без необходимости
- Нельзя трогать config.py.
- Никогда не коммитить реальные ключи, только пример/шаблон
- Не трогать файлы/папки, не связанные с задачей
- Не делать массовые рефакторинги “заодно”
- Агент изменяет только файлы, непосредственно связанные с задачей.
- Если требуется изменение других модулей — агент должен указать это в PR.
- Если инструкции задачи противоречат AGENTS.md — приоритет у AGENTS.md.

---

## 🔐 Конфиги и секреты

- Файл `config.py` содержит реальные ключи и находится в `.gitignore`.
- `config.py` никогда не коммитится в репозиторий.

- В репозитории хранится только шаблон конфигурации:
  - `config_example.py`

Файл `config_example.py` содержит:
- список всех необходимых переменных
- пустые значения или заглушки
- не содержит секретов

---

## ⚠️ Правила работы с конфигурацией

AI агенту запрещено:

- создавать или коммитить `config.py`
- добавлять реальные ключи, токены, пароли или DSN строки
- логировать секреты
- выводить секреты в консоль
- изменять способ хранения секретов

---

## 🧩 Добавление новых конфигурационных параметров

Если задаче требуется новый параметр конфигурации:

AI агент обязан:

1. Добавить переменную в `config_example.py`
2. Обновить код, который использует конфигурацию
3. Использовать безопасные значения по умолчанию, если возможно
4. Не создавать `config.py`

---

## 🤖 Ограничения доступа для AI агента

Агент должен использовать только креды с ограниченными правами:

- Только dev/stage токены
- Где возможно — read-only доступ
- Запрещено использовать прод креды

---

## 🔒 Ограничения доступа к данным

Для баз данных:

Разрешено:
- SELECT
- INSERT только в таблицы, используемые для агрегированных результатов

Запрещено:
- UPDATE
- DELETE
- ALTER
- DROP


Для внешних API:

- Разрешено только получение данных
- Запрещены операции изменения данных (если применимо)

---

## 🧰 Поведение при отсутствии конфигурации

Если запуск тестов требует секретов, которые отсутствуют:

AI агент обязан:

1. Не изменять бизнес-логику ради прохождения тестов
2. Сообщить, какие переменные конфигурации отсутствуют
3. Предложить mock или тестовые данные
4. Сделать тесты независимыми от реальных API вызовов, если возможно

---

## 🧪 Тестирование

Любая новая логика ОБЯЗАНА иметь тест.

После внесения изменений агент обязан запустить:

pytest

Изменения запрещены, если тесты падают.

---

## 🧹 Линтинг

Перед коммитом агент обязан выполнить:

ruff check . --fix

---

## 🚀 Команда полной проверки

Агент должен запускать:

ruff check . --fix
pytest

---

## 💬 Формат commit сообщений

Коммиты должны иметь формат:

<тип>: <краткое описание>

Типы:

feat – новая функциональность  
fix – исправление багов  
refactor – рефакторинг  
test – добавление тестов  
docs – документация  

Пример:

feat: add google ads analysis

fix: correct order aggregation logic

---

## 🔐 Ограничения безопасности

AI агенту запрещено:

- Изменять конфигурации прод окружения
- Добавлять секреты в код
- Менять инфраструктуру
- Изменять файлы CI/CD без явной задачи

---

## ⚙️ Правила внесения изменений

Перед завершением задачи агент должен:

1. Реализовать код
2. Добавить тесты
3. Запустить проверки
4. Убедиться, что тесты проходят
5. Сделать commit
6. Запушить ветку

---

## 📦 Работа с зависимостями

Добавлять новые зависимости можно только если:

- нет альтернативы внутри проекта
- зависимость широко используется
- обязательно добавить новую зависимость в requirements

---

## 🧾 Описание Merge Request

Merge request должен содержать:

- Краткое описание изменений
- Ссылку на задачу Jira
- Описание бизнес логики изменений
