# Несогласованность единиц массового и объёмного расхода в формуле Писмана

## Симптом

При закачке 1000 кг/день воды (Q_vol = 1 м³/день) в 1D задаче Бакли-Леверетта эффективная скорость Дарси qt_eff ≈ 0.0036 м/день — в ~280 раз меньше ожидаемой. Фронт вытеснения проходит ~8 м за 400 дней вместо ожидаемых ~200+ м.

## Цепочка пересчёта единиц

### MER → curFluidDebit

```
MER запись: oil_m = 800·30.74 кг, water_m = -1000·30.74 кг (за месяц)
curFluidDebit = {oil_m, water_m} / MER_interval · convert2SI
convert2SI = debitConversion = 1.0
→ curFluidDebit = {800, -1000} кг/день
→ curDebitOverall = 800 + (-1000) = -200 кг/день
```

### Внутренние единицы солвера

- Вязкость: μ_w = 2.0 мПа·с × (1/86400/1000) = 2.315e-8 Па·день
- Проницаемость: k = 100 мД × 0.9869e-15 = 9.869e-14 м²
- Подвижность: λ = k·kr/μ [м²/(Па·день)]
- factor (PI Писмана): h_perf · 2π / ln(r_app/r_well) [м]
- production = factor · λ · ΔP [м · м²/(Па·день) · Па] = **м³/день**

### SetRefWellPressure — место ошибки

```cpp
double numer = -CurOverallDebit();    // +200 [кг/день]
for (l : perforations)
    numer += factor[l] * OverallMobility(l) * P_Reservoir(l);  // [м³/день]
```

**numer складывает кг/день и м³/день** — несоразмерные величины.

Формула Писмана предполагает:
$$P_{well} = \frac{-Q_{vol} + \sum_l PI_l \cdot \lambda_l \cdot P_{res,l}}{\sum_l PI_l \cdot \lambda_l}$$

где $Q_{vol}$ в м³/день. Но `CurOverallDebit()` возвращает кг/день.

### Количественная оценка

- factor · λ (при Sw=0.2, kr_w=0.008): ~3.86e-5 м³/(Па·день)
- factor · λ · P_res (P_res ~ 2e7 Па): ~772 м³/день
- numer = 200 [кг/день] + 772 [м³/день] (несогласованные единицы)
- denom = 3.86e-5 м³/(Па·день)
- P_well ≈ (200 + 772) / 3.86e-5 ≈ P_res - δP

Поскольку 772 ≫ 200, P_well ≈ P_res и ΔP мало. Эффективный объёмный расход `factor·λ·ΔP ≈ 200 · (3.86e-5 / 3.86e-5)` ≈ 200 «единиц» потока (но интерпретируемых как м³/день в уравнениях транспорта, а заданных как кг/день).

Фактически солвер думает, что нужно прокачать 200 м³/день вместо 0.2 м³/день (Q_mass/ρ), но поскольку PI мало, это требует огромного ΔP, и реальное вытеснение оказывается слабым.

## Почему тест VAL-001 всё-таки проходит

Тест вычисляет qt_eff из баланса масс GDM и строит аналитику относительно этого qt_eff. Это проверяет **форму профиля и порядок сходимости**, но не абсолютный расход. Баг размерностей компенсируется подстройкой qt_eff.

## Варианты исправления

### Вариант A: пересчёт в MER_Descriptor
В `identify_cur_MER_record` делить масcовый расход на плотность смеси:
```
curFluidDebit.oil /= oil_density;
curFluidDebit.water /= water_density;
```
→ CurOverallDebit() в м³/день.

### Вариант B: пересчёт в SetRefWellPressure
Делить CurOverallDebit() на ρ_mix при подстановке в формулу Писмана.

### Вариант C: MER в объёмных единицах
Задавать MER сразу в м³/день (поля `oil_v`, `water_v` уже есть в записях). Изменить `identify_cur_MER_record` для использования объёмных полей.

**Рекомендация:** вариант A — единственная точка пересчёта, минимум изменений. Вариант C — чище, но требует ревизии всех мест создания MER.
