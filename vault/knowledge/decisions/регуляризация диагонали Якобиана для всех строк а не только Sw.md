# Регуляризация диагонали Якобиана для всех строк, а не только Sw

## Контекст

При Sw=0 с несжимаемыми фазами (CompressibilityWater = CompressibilityOil = 0) строка WaterEq в Якобиане имеет нулевую диагональ по давлению: `dWaterEq/dP = 0` (нет водного потока, нет сжимаемости → нет зависимости от давления). Скалярный ILU0 требует ненулевых пивотов на диагонали.

## Проблема

Исходная регуляризация итерировала только нечётные строки CRS-матрицы:
```cpp
for (size_t i = 1; i < rhsSize; i += B)
```

В layout InterleavedPSw (используемом GDM) перестановка CRS→Physical = {1, 0}:
- **Чётные строки** (i=0,2,4,...) = WaterEq (physRow=1)
- **Нечётные строки** (i=1,3,5,...) = OilEq (physRow=0)

Итерация `i += B` с `i=1` обрабатывала только OilEq-строки, чья диагональ всегда ненулевая. WaterEq-строки с нулевой диагональю оставались без регуляризации → zero pivot в ILU0 → плохой прекондиционер → GMRES дивергирует → NaN.

## Решение

Регуляризация для **всех** строк:
```cpp
for (size_t i = 0; i < rhsSize; ++i) {
    // if abs(diag) < 1e-20, set to 1e-6
}
```

Это безопасно: для строк с ненулевой диагональю (|diag| >> 1e-20) проверка не срабатывает. Для вырожденных строк — восстанавливает регулярность.

## Альтернатива (отвергнута)

Fallback `if (is_zero(D[i])) D[i] = 1` внутри ILU0 (BUG-002 патч). Отвергнут потому что:
1. Маскирует проблему внутри библиотеки вместо решения на уровне задачи
2. Экспериментально показано: при корректной регуляризации в LinearProblem fallback в ILU0 не срабатывает
3. ilu0.hpp возвращён к upstream — чистая зависимость
