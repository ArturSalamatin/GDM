# Команда /plan-fix для планирования исправления багов

## Назначение

Построение детализированного плана исправления бага, готового к автономной реализации в отдельной сессии.

## Расположение

`.claude/commands/plan-fix.md`

## Аргумент

`BUG-NNN` или номер GitHub issue (`#1`).

## Фазы работы

1. **Сбор контекста** — vault-запись, GitHub issue, связанные заметки, исследование кода
2. **Анализ** — воспроизведение, цепочка причин, варианты решения, 10-точечный чеклист подводных камней
3. **Детализация** — пошаговый план: подготовка → минимальный фикс → тесты → архитектурное решение → верификация → очистка
4. **Верификация** — 3 раунда: полнота, корректность, автономность
5. **Сохранение** — файл в `vault/GDM/plans/`, обратные ссылки

## Ключевые принципы

- Каждый шаг ≤ 50 строк изменений
- Структура шага: цель, файлы, контекст, действия, старый→новый код, проверка, подводные камни
- Тестовая стратегия: тест-воспроизводитель + граничные + инвариантные + regression + visual
- Файл плана самодостаточен для Claude в новой сессии без контекста

## Отличие от /plan-improve

| | /plan-fix | /plan-improve |
|---|---|---|
| Отправная точка | сломанное поведение | работающий код |
| Первый шаг | воспроизвести баг | зафиксировать baseline |
| Инвариант | тест был красный, стал зелёный | все тесты зелёные на каждом шаге |
