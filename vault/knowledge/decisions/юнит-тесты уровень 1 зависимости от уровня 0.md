# Юнит-тесты: уровень 1 — зависимости от уровня 0

Классы этого уровня зависят от типов уровня 0 (STL + простые value-types проекта). Для тестирования нужно создать объекты уровня 0, но не требуется полноценная инфраструктура (сетки, солверы, скважины).

Связано: [[граф зависимостей классов gdm_core]], [[юнит-тесты уровень 0 нулевые зависимости]]

---

## 1. SetOfPoints

**Файл:** `Reservoir/Well/SetOfPoints.h` (строки 62–113), `Reservoir/Well/SetOfPoints.cpp`

**Пространство имён:** `set_of_points`

**Зависимости → уровень 0:** `Segment`, `WellJob`

**Описание:** Реализация sweep-line алгоритма для объединения/вычитания отрезков на прямой. Используется для вычисления текущей конфигурации перфораций скважины. Внутреннее представление — массив `Ray` (начало/конец отрезка с типом +1/-1/±∞).

**Что тестировать:**

### Конструктор
- `SetOfPoints(WellJob({10, 30}, true))` — один открытый отрезок
- `SetOfPoints(WellJob({10, 30}, false))` — один закрытый (удаляющий) отрезок

### AddSegment
- Добавление непересекающихся открытых отрезков: `[10,20] + [30,40]` → два отрезка
- Добавление перекрывающихся: `[10,30] + [20,40]` → `[10,40]` после Sweep
- Закрытие части: open `[10,40]`, close `[20,30]` → `[10,20] + [30,40]`
- Закрытие всего: open `[10,30]`, close `[10,30]` → пусто
- Закрытие за пределами: open `[10,30]`, close `[0,50]` → пусто

### Sweep
- Проверка после серии AddSegment: `getCurrentConfiguration()` возвращает корректные сегменты
- Пустой набор: `Sweep()` на пустом → 0 сегментов

### totalLength
- Сумма длин всех отрезков
- Пустой набор → 0

### operator==
- Два одинаковых набора → true
- Разные наборы → false

**Примерные тесты:**
```cpp
SetOfPoints sp(WellJob({10.0, 30.0}, true));
sp.AddSegment(WellJob({20.0, 40.0}, true));
sp.Sweep();
auto& segments = sp.getCurrentConfiguration();
CHECK(segments.size() == 1);  // объединились
CHECK(segments[0].start == 10.0);
CHECK(segments[0].end == 40.0);
CHECK(sp.totalLength() == 30.0);

// закрытие середины
SetOfPoints sp2(WellJob({10.0, 40.0}, true));
sp2.AddSegment(WellJob({20.0, 30.0}, false));
sp2.Sweep();
CHECK(sp2.getCurrentConfiguration().size() == 2);
CHECK(sp2.totalLength() == Approx(20.0));
```

## 2. SetOfPerforations

**Файл:** `Reservoir/Well/SetOfPoints.h` (строки 119–139), `Reservoir/Well/SetOfPoints.cpp`

**Пространство имён:** `set_of_points`

**Зависимости → уровень 0:** `SetOfPoints`, `WellJobTime`

**Описание:** Конфигурация перфораций скважины на определённый момент времени. Содержит `SetOfPoints` (текущие открытые интервалы) и `timeMoment`.

**Что тестировать:**

### Конструктор
- `SetOfPerforations(WellJobTime(10, 30, true, 100))` — перфорация с t=100
- `SetOfPerforations()` — дефолтный (закрытое состояние)

### AddNewJob
- Последовательное открытие: t=100 open [10,30], t=200 open [20,40] → объединение
- Закрытие: t=100 open [10,40], t=200 close [20,30] → разделение

### MoveDate
- Перенос даты без изменения конфигурации

### JoinPerforations
- Слияние перфораций из разных слоёв

### TotalLength / curTime
- Геттеры

### operator==
- Сравнение по перфорациям и времени

**Примерные тесты:**
```cpp
SetOfPerforations sp(WellJobTime(10.0, 30.0, true, 100.0));
CHECK(sp.curTime() == 100.0);
CHECK(sp.TotalLength() == 20.0);

sp.AddNewJob(WellJobTime(20.0, 40.0, true, 200.0));
CHECK(sp.TotalLength() == 30.0);  // [10,40]
CHECK(sp.curTime() == 200.0);
```

## 3. RawHorizon

**Файл:** `Solver/Grids/RawHorizon.h`

**Зависимости → уровень 0:** `GridDescriptors` (`GridSize`, `GridShift`, `GridBounds`, `BlockSize`), `PropertyDescriptor` (`OilPhaseProperty`, `WaterPhaseProperty`, `OtherProperties`)

**Описание:** Сырые данные горизонта пласта: размеры сетки, физические свойства (пористость, проницаемость), начальные условия (давление, насыщенность), координаты ячеек. Все поля публичные — это data-класс.

**Что тестировать:**

### GridSize / GridPlanarSize
- `RawHorizon` с `grid_size = {Nx=5, Ny=3, Nz=2}` → `GridSize() == 30`, `GridPlanarSize() == 15`
- `nx() == 5`, `ny() == 3`

### initial_water_saturation
- `initial_oil_saturation = {0.8, 0.6, 1.0}` → `initial_water_saturation() == {0.2, 0.4, 0.0}`
- Инвариант: `S_oil + S_water == 1.0` для каждой ячейки

**Примерные тесты:**
```cpp
RawHorizon h;
h.grid_size = {5, 3, 2};
CHECK(h.GridSize() == 30);
CHECK(h.GridPlanarSize() == 15);

h.initial_oil_saturation = {0.8, 0.6, 1.0};
auto sw = h.initial_water_saturation();
CHECK(sw[0] == Approx(0.2));
CHECK(sw[1] == Approx(0.4));
CHECK(sw[2] == Approx(0.0));
```

## 4. SchemeParameters

**Файл:** `Descriptors/Descriptors.h`, `Descriptors/Descriptors.cpp`

**Зависимости → уровень 0:** `GridDescriptors.h`, `PropertyDescriptor.h` (через include, но не использует типы напрямую)

**Описание:** Параметры численной схемы: допуски Ньютона, AMG, минимальные свойства ячеек.

**Что тестировать:**

### Конструктор + геттеры
- `SchemeParamaters(1e-4, 12, 1e-2, 1e-2, 0.1, 0.01, 1e-15)`
- `RequiredNewtonTol() == 1e-4`
- `NewtonMaxIterCount() == 12`
- `AMG_RelTol() == 1e-2`, `AMG_AbsTol() == 1e-2`
- `MinCellThickness() == 0.1`, `MinPorosity() == 0.01`, `MinPermeability() == 1e-15`

### Дефолтный конструктор
- Значения из protected-секции (внимание: комментарии к полям не соответствуют смыслу — `requiredNewtonTol = 1E5` помечен как "Pa", но это толеранс Ньютона)

## 5. FluidDebit, TimeFrame (defines.h)

**Файл:** `defines.h` (пространство `reservoir_simulator::mer_descriptor`)

**Зависимости → уровень 0:** `GeosPoint.h`, `SetOfPoints.h` (через include)

**Описание:**
- `FluidDebit{oil, water}` — дебит фаз в кг. Операторы `*`, `/`, `+`. Статический `SetFromVolume(o_v, w_v)` (конверсия объём → масса: oil*800, water*1000).
- `TimeFrame{start, end}` — временной интервал с конверсией в `pair<double,double>`

**Что тестировать:**

### FluidDebit
- `FluidDebit{100, 200} * 2.0` → `{200, 400}`
- `FluidDebit{100, 200} / 2.0` → `{50, 100}`
- `FluidDebit{100, 200} + FluidDebit{50, 30}` → `{150, 230}`
- `SetFromVolume(10.0, 5.0)` → `{8000.0, 5000.0}`

### TimeFrame
- `TimeFrame{100.0, 365.0}` — конверсия `operator pair<double,double>()` → `{100.0, 365.0}`

## 6. MathRoutines (статические методы)

**Файл:** `Solver/Math/MathRoutines.h`, `Solver/Math/MathRoutines.cpp`

**Пространство имён:** `math_routines`

**Зависимости → уровень 0:** `Point.h` (Point, trPoint, Direction)

**Описание:** Статические утилиты: линейная и билинейная интерполяция, поиск по uniform/non-uniform сетке, ODE-интеграторы (Euler2, RK4).

**Что тестировать (приоритет — статические не-template методы):**

### LinearInterp
- `LinearInterp(0.5, 0.0, 1.0, 10.0, 20.0)` → `15.0`
- Экстраполяция: `query_t` вне `[t1, t2]`
- Пара: `LinearInterp(0.5, 0.0, 1.0, {1.0, 2.0}, {3.0, 4.0})` → `{2.0, 3.0}`

### BilinearInterp
- 4 узла прямоугольника с известными значениями, интерполяция в центре

### LowerPointUniformMesh
- Равномерная сетка `{0, 1, 2, 3, 4}`, запрос `2.5` → индекс 2
- Граница: запрос `0.0` → 0, запрос `3.99` → 3

### LowerPointNonUniformMesh
- Неравномерная сетка `{0, 1, 5, 10}`, запрос `3.0` → индекс 1

**Примерные тесты:**
```cpp
double v = MathRoutines::LinearInterp(0.5, 0.0, 1.0, 10.0, 20.0);
CHECK(v == Approx(15.0));

std::vector<double> mesh = {0, 1, 2, 3, 4};
CHECK(MathRoutines::LowerPointUniformMesh(mesh, 2.5) == 2);
CHECK(MathRoutines::LowerPointUniformMesh(mesh, 0.0) == 0);
```

## 7. DebitConversion2SI

**Файл:** `Descriptors/MER_Descriptor.h`

**Зависимости:** нет (standalone)

**Описание:** Константа конверсии дебита. `debitConversion = 1.0` (кг/день — уже в SI-совместимых единицах). Метод `convert2SI()`.

**Что тестировать:**
- `DebitConversion2SI().convert2SI() == 1.0`

(Тривиально, но покрывает на случай изменения конвенции единиц в будущем.)

## Порядок реализации

1. **SetOfPoints** — ключевой алгоритм sweep-line, используется повсюду в скважинах
2. **SetOfPerforations** — следующий слой над SetOfPoints
3. **FluidDebit / TimeFrame** — простая арифметика, быстро
4. **RawHorizon** — data-класс, тривиальные тесты
5. **MathRoutines** — интерполяция, важна для верификации
6. **SchemeParameters** — конструктор + геттеры
7. **DebitConversion2SI** — тривиально
