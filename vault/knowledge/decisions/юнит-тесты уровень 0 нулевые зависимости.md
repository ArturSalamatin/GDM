# Юнит-тесты: уровень 0 — нулевые зависимости

Классы этого уровня зависят только от STL. Их можно тестировать полностью изолированно, без создания каких-либо объектов из других модулей проекта.

Связано: [[граф зависимостей классов gdm_core]]

---

## 1. PIController + PIControllerParams

**Файлы:** `Reservoir/PIController.h`, `Reservoir/PIController.cpp`

**Зависимости:** `<algorithm>`, `<cmath>` — только STL.

**Описание:** PI-контроллер адаптивного шага по времени (формула Söderlind). Регулирует множитель `dt` на основе числа итераций Ньютона.

**Что тестировать:**
- `ComputeMultiplier(iters, success=true)`:
  - `iters == target` → множитель ≈ 1.0
  - `iters < target` → множитель > 1.0 (увеличение шага)
  - `iters > target` → множитель < 1.0 (уменьшение шага)
  - Clamping: множитель ∈ [`min_shrink`, `max_growth`] = [0.3, 2.0]
- `ComputeMultiplier(iters, success=false)`:
  - Всегда возвращает `min_shrink` = 0.3
- `Reset()`:
  - После Reset первый вызов не использует prev_error_ (P-компонента только)
- Конструктор: `PIController(params)` — проверка хранения параметров через `Params()`

**Примерные тесты:**
```cpp
PIController pi({.alpha=0.7, .beta=0.2, .target_iters=12, .max_growth=2.0, .min_shrink=0.3});
// первый вызов — только P-компонента
double m1 = pi.ComputeMultiplier(6, true);  // iters < target → > 1
CHECK(m1 > 1.0);
CHECK(m1 <= 2.0);
// второй вызов — PI-компонента
double m2 = pi.ComputeMultiplier(12, true); // iters == target → ≈ 1
CHECK(m2 == Approx(1.0).margin(0.3));
// failure
double m3 = pi.ComputeMultiplier(20, false);
CHECK(m3 == Approx(0.3));
```

## 2. GridDescriptors (POD-типы)

**Файл:** `Solver/Grids/GridDescriptors.h`

**Зависимости:** `<cmath>`, `<vector>` — только STL. Header-only.

**Описание:** Набор POD-типов для описания сетки:
- `GridSize` — `{Nx, Ny, Nz}`
- `GridShift` — `{shiftX, shiftY}`
- `GridBounds` — `{x_min, y_min, x_max, y_max}` + вычисление `x_length`, `y_length`
- `BlockSize` — `{step_x, step_y}`
- Type aliases: `PorosityData`, `PermeabilityData`, `ActiveCellData`, etc. = `std::vector<double/bool>`

**Что тестировать:**
- `GridBounds` конструктор: `x_length = |x_max - x_min|`, `y_length = |y_max - y_min|`
- `GridBounds` дефолтный конструктор: все нули
- `GridBounds` с отрицательными координатами: `x_length` всё равно положительна (`std::abs`)
- `GridSize`, `BlockSize` — POD, можно проверить aggregate initialization

**Примерные тесты:**
```cpp
GridBounds gb(100.0, 200.0, 500.0, 600.0);
CHECK(gb.x_length == 400.0);
CHECK(gb.y_length == 400.0);

GridBounds gb_neg(-100.0, -200.0, 100.0, 200.0);
CHECK(gb_neg.x_length == 200.0);
CHECK(gb_neg.y_length == 400.0);

GridBounds gb_default;
CHECK(gb_default.x_length == 0.0);
```

## 3. PropertyDescriptor (PhaseProperties, CustomUnitConverter, OtherProperties)

**Файл:** `Solver/Grids/PropertyDescriptor.h`

**Зависимости:** нет (header-only, только STL).

**Описание:**
- `CustomUnitConverter` — статический конвертер вязкости: `from_mPas_2_PaDay = 1 / 86400 / 1000`
- `PhaseProperties<CustomUnitConverter>` — параметры фазы (вязкость, плотность, сжимаемость, остаточная доля, опорное давление). Вязкость конвертируется при создании.
- `OtherProperties` — g = 9.81, extPressure = 101325 Па
- Aliases: `WaterPhaseProperty = PhaseProperties<CustomUnitConverter>`, аналогично `OilPhaseProperty`

**Что тестировать:**
- `CustomUnitConverter::viscosityConverter()` → `1.0 / 86400000.0`
- `PhaseProperties` конструктор: вязкость = `visc * viscosityConverter()`, остальные поля = as-is
- Все геттеры: `Viscosity()`, `Density()`, `Compressibility()`, `ResidualFraction()`, `ReferencePressure()`
- `OtherProperties` дефолтные значения: `g == 9.81`, `extPressure == 101325`
- Дефолтный конструктор `PhaseProperties()`: значения по умолчанию из protected-секции

**Примерные тесты:**
```cpp
WaterPhaseProperty water(1.0/*mPa.s*/, 1000.0/*kg/m3*/, 0.0, 0.2, 1e5);
CHECK(water.Viscosity() == Approx(1.0 / 86400.0 / 1000.0));
CHECK(water.Density() == 1000.0);
CHECK(water.ResidualFraction() == 0.2);
CHECK(water.ReferencePressure() == 1e5);
```

## 4. Point, trPoint, Contour, Coordinate, geos_polygon

**Файл:** `Anomaly/FlowField/Point.h`

**Зависимости:** `<array>`, `<vector>`, `<string>`, `<cmath>` — только STL. Header-only (кроме Point.cpp для статических/utility-методов, если есть).

**Пространство имён:** `reservoir_simulator::phasePortrait`

**Описание:**
- `Point(x, y)` — 2D-точка. Методы: `x()`, `y()`, `distance(p)`, `Area(P)`, static `Area(P, Q)`, static `Area(P, array<Point,4>)`
- `trPoint(t, s, Point/x,y)` — точка на траектории с временем и пройденным расстоянием. `operator+`, `operator/`, `Move(direction, dt)`, `is_normal()`
- `Contour(x_vec, y_vec)` — набор точек. `size()`, `x()`, `y()`
- `Coordinate{x, y}` — POD
- `geos_polygon` — заглушка GEOS. `contains`/`intersects` → false, `Union`/`combine_with` → `*this`

**Что тестировать:**
- `Point::distance`: `Point(0,0).distance(Point(3,4)) == 5.0`
- `Point::Area`: `|dx * dy|`
- `trPoint::Move`: `(t+dt, s+dt*dir[0], x+dt*dir[1], y+dt*dir[2])`
- `trPoint::is_normal`: true для конечных, false если NaN/Inf
- `trPoint::operator+`, `operator/`
- `Contour::size()` == количество точек
- `geos_polygon::contains()` == false (заглушка)

**Примерные тесты:**
```cpp
Point p1(0, 0), p2(3, 4);
CHECK(p1.distance(p2) == Approx(5.0));
CHECK(Point::Area(Point(0,0), Point(3,4)) == 12.0);

trPoint tp(0, 0, 1.0, 2.0);
Direction dir = {1.0, 0.5, -0.5};
auto moved = tp.Move(dir, 2.0);
CHECK(moved.t() == 2.0);
CHECK(moved.s() == 2.0);
CHECK(moved.x() == 2.0);  // 1.0 + 2.0*0.5
CHECK(moved.y() == 1.0);  // 2.0 + 2.0*(-0.5)
CHECK(moved.is_normal());

trPoint bad(std::numeric_limits<double>::infinity(), 0, 0, 0);
CHECK_FALSE(bad.is_normal());
```

## 5. Segment, WellJob, WellJobTime

**Файл:** `Reservoir/Well/SetOfPoints.h` (строки 8–60), `Reservoir/Well/SetOfPoints.cpp`

**Пространство имён:** `set_of_points`

**Зависимости:** `stdafx.h` (precompiled headers, STL only), `LogFile.h` (статические методы, побочный эффект — вывод в лог).

**Описание:**
- `Segment(start, end)` — отрезок на прямой. `length()`, `segment()` → `pair<double,double>`, `operator==`
- `WellJob(segment, is_open)` — операция скважины: открытие или закрытие отрезка перфорации. `isOpen()`
- `WellJobTime(segment, is_open, time)` : `WellJob` + время. `sortOperator(a, b)`, `TransferDate(newTime)`

**Что тестировать:**
- `Segment(10, 30)` → `length() == 20`, `segment() == {10, 30}`, `operator==`
- `Segment(30, 10)` — проверить поведение при start > end (если length = end - start, будет отрицательной)
- `WellJob({10, 30}, true)` → `isOpen() == true`
- `WellJob({10, 30}, false)` → `isOpen() == false`
- `WellJobTime::sortOperator` — сортировка по времени
- `WellJobTime::TransferDate` — перенос даты

**Примерные тесты:**
```cpp
Segment s(10.0, 30.0);
CHECK(s.length() == 20.0);
CHECK(s.segment() == std::make_pair(10.0, 30.0));
CHECK(s == Segment(10.0, 30.0));
CHECK_FALSE(s == Segment(10.0, 25.0));

WellJob open_job(s, true);
CHECK(open_job.isOpen());
WellJob close_job(s, false);
CHECK_FALSE(close_job.isOpen());

WellJobTime jt1(10.0, 30.0, true, 100.0);
WellJobTime jt2(10.0, 30.0, true, 200.0);
CHECK(WellJobTime::sortOperator(jt1, jt2)); // jt1 раньше
```

## 6. GeosPoint / SimplePoint

**Файл:** `Data/wells/GeosPoint.h`

**Зависимости:** `<memory>` — только STL. Header-only.

**Пространство имён:** `GeosShell`

**Описание:** Заглушка для GEOS-библиотеки.
- `SimplePoint(x, y)` — хранит координаты. `getX()`, `getY()`
- `GeosPoint(x, y)` — обёртка через `shared_ptr<SimplePoint>`. `get()` → shared_ptr

**Что тестировать:**
- `SimplePoint` конструкторы: дефолтный (0, 0), с параметрами
- `GeosPoint` конструкторы: дефолтный, с параметрами
- `GeosPoint::get()->getX()` == x, `get()->getY()` == y
- Копирование `GeosPoint`: shared_ptr разделяется (use_count == 2)

**Примерные тесты:**
```cpp
SimplePoint sp(3.5, 7.2);
CHECK(sp.getX() == 3.5);
CHECK(sp.getY() == 7.2);

GeosPoint gp(10.0, 20.0);
CHECK(gp.get()->getX() == 10.0);
CHECK(gp.get()->getY() == 20.0);

GeosPoint gp2 = gp; // shared
CHECK(gp.get().use_count() == 2);
```

## Рекомендуемый порядок реализации тестов

1. **PIController** — самый чистый: 2 метода, чистая математика, есть `.cpp`
2. **GridBounds** — 1 конструктор, POD
3. **PhaseProperties + CustomUnitConverter** — конвертация единиц
4. **Point / trPoint** — геометрия
5. **Segment / WellJob / WellJobTime** — value-types
6. **GeosPoint** — тривиально

Каждый класс тестируется: конструктор → методы → граничные случаи → operator== (если есть).
