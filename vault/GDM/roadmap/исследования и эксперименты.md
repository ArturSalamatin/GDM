# Исследования и эксперименты

Реестр численных экспериментов и исследовательских задач. Каждый эксперимент — проверка гипотезы, изучение поведения модели или оценка альтернативного подхода. В отличие от FEAT (решение принято, нужно реализовать), исследование может не привести к коду в main.

Результат исследования — вывод: «делать фичу / не делать / нужно больше данных».

---

## Численные схемы

### RES-001: Сравнение upstream vs TVD для транспорта
- **Гипотеза:** TVD-реконструкция (minmod/superbee) уменьшит численную диффузию фронта Sw
- **Эксперимент:** 1D Buckley–Leverett, upstream vs TVD, серия сеток
- **Метрика:** ширина размытия фронта, порядок сходимости, overhead по времени
- **Зависимости:** VAL-001, VAL-002 (нужен работающий 1D кейс для baseline)
- **Если подтвердится:** FEAT для TVD-схемы транспорта
- **Статус:** ⬜ НЕ НАЧАТО

### RES-002: IMPES vs полностью неявная на мелких сетках
- **Гипотеза:** IMPES (давление неявно, насыщенность явно) может быть быстрее на мелких сетках за счёт меньшего размера системы
- **Эксперимент:** 21×21, 51×51 five-spot, IMPES vs FI, время vs точность
- **Метрика:** wall-clock, количество Newton-итераций, ошибка Sw vs fine-grid
- **Подробности:** [[схема дискретизации полностью неявная а не IMPES]]
- **Если подтвердится:** FEAT для IMPES-режима
- **Статус:** ⬜ НЕ НАЧАТО

## Солвер

### RES-003: AMG vs ILU(k) для давления в CPR
- **Гипотеза:** ILU(2) может быть конкурентоспособен с AMG на сетках < 50k при меньшем overhead на setup
- **Эксперимент:** five-spot 21×21..101×101, CPR<AMG,ILU0> vs CPR<ILU2,ILU0>
- **Метрика:** число итераций, wall-clock, setup time
- **Подробности:** [[amgcl конфигурация iluk k1 новый оптимум]]
- **Если подтвердится:** добавить конфигурируемый выбор прекондиционера давления
- **Статус:** ⬜ НЕ НАЧАТО

### RES-004: Чувствительность к параметрам PI-контроллера
- **Гипотеза:** текущие safety=1, target=12 — локальный оптимум; возможно, target=8–10 даёт меньше wasted trials
- **Эксперимент:** five-spot, серия (safety, target), подсчёт wasted trials, total Newton iters, wall-clock
- **Подробности:** [[PI-контроллер safety=1 и target=12 для Newton-based timestep control]]
- **Если подтвердится:** обновить default-параметры
- **Статус:** ⬜ НЕ НАЧАТО

## Физика

### RES-005: Влияние капиллярного давления на фронт вытеснения
- **Гипотеза:** Pc(Sw) сглаживает фронт и замедляет прорыв; при Pc=0 результат совпадает с Buckley–Leverett
- **Эксперимент:** 1D, Leverett J-function, серия параметров σ√(k/φ)
- **Метрика:** профиль Sw, время прорыва, сравнение с аналитикой (если есть)
- **Зависимости:** FEAT-005 (капиллярное давление должно быть реализовано)
- **Если подтвердится:** валидационный кейс VAL-NNN
- **Статус:** ⬜ НЕ НАЧАТО

## Критерии сходимости

### RES-006: Ревизия критерия сходимости Ньютона вблизи границ насыщенности
- **Гипотеза:** текущий критерий `|Sw| < 3E-7` или `|1-Sw| < 3E-7` принимает состояние как сошедшееся вблизи Sw=0/1, даже если коррекция ещё значима — это может маскировать проблемы конвергенции
- **Эксперимент:** five-spot с Sw_init ≈ 0, логирование коррекций Ньютона на каждой итерации, сравнение с ужесточённым критерием
- **Метрика:** число ложных сходимостей, качество решения вблизи Sw=0/1, влияние на wasted trials
- **Файл:** `ReservoirSimulator.cpp:456-481`
- **Подробности:** [[code-review-2026-06-28-числовая-устойчивость]]
- **Если подтвердится:** исправить критерий, обновить абсолютный порог давления
- **Статус:** ⬜ НЕ НАЧАТО

### RES-007: CPR+BiCGStab vs CPR+LGMRES — может ли BiCGStab стать default
- **Гипотеза:** CPR+BiCGStab даёт сопоставимую точность при ~30% экономии времени по сравнению с CPR+LGMRES на типичных задачах GDM
- **Эксперимент:** five-spot 51×51×4, single injector, variable debit — прогнать оба солвера, сравнить число итераций Ньютона, итераций солвера, время, точность
- **Метрика:** wall-clock time, iters/timestep, residual, баланс масс
- **Зависимости:** DEBT-053 ✅
- **Если подтвердится:** изменить default GDM_SOLVER=CPR_BICGSTAB, обновить vault
- **GitHub:** [#27](https://github.com/ArturSalamatin/GDM/issues/27)
- **Ветка:** research/res-007/bicgstab-vs-lgmres
- **План:** [[res-007 bicgstab-vs-lgmres]]
- **Статус:** ⬜ НЕ НАЧАТО

### RES-008: Блочный backend amgcl (`static_matrix<2,2>`) vs скалярный (`double`)
- **Гипотеза:** переход с `builtin<double>` + `prm.block_size=2` на `builtin<static_matrix<2,2>>` ускорит CPR setup на ≥15% за счёт compile-time B: разворачивание циклов, `%2` → `&1`, `/ 2` → `>>1`, векторизация в `first_scalar_pass` и `update_transfer`
- **Эксперимент:** five-spot 51×51×4, single injector 41×41 — profiling CPR setup (amgcl profiler). Baseline: scalar path. Target: static block path. Варьируем: только backend, остальные параметры фиксированы
- **Метрика:** wall-clock time CPR setup, wall-clock time total solve, число GMRES-итераций (должно быть идентичным — тот же алгоритм)
- **Зависимости:** FEAT-011 (True-IMPES weights). Переделка затрагивает `MatrixCSR`, assembly в `ReservoirSimulator`, `LinearProblem.cpp` — нужно переупаковать скалярный Якобиан в блочный CRS
- **Если подтвердится:** DEBT (рефакторинг `LinearProblem` на блочный backend) или FEAT (блочная сборка Якобиана напрямую)
- **Если не подтвердится:** scalar path достаточен, overhead от runtime B пренебрежим
- **Статус:** ⬜ НЕ НАЧАТО

## Как добавить эксперимент

Формат записи:
```

- **Гипотеза:** что проверяем (одно предложение, фальсифицируемое)
- **Эксперимент:** сетка, параметры, что варьируем
- **Метрика:** что измеряем, как сравниваем
- **Зависимости:** VAL-NNN / BUG-NNN / FEAT-NNN (если есть)
- **Подробности:** [[wiki-ссылка]] (если есть заметка)
- **Если подтвердится:** какое действие (FEAT, изменение default, новый VAL)
- **GitHub:** [#N](url) (после создания issue)
- **План:** [[имя плана]] (после /plan-research)
- **Статус:** ⬜ НЕ НАЧАТО | 🔧 В РАБОТЕ | ✅ ЗАВЕРШЕНО | ❌ ОТВЕРГНУТО
```
