# Roadmap — долгосрочный план развития GDM

Документ фиксирует стратегию развития симулятора от текущего состояния до полноценного инструмента для моделирования многопластовых месторождений. Каждая фаза — законченный этап с чёткими критериями завершения.

## Фаза 3: Стабилизация ядра — 📋 ТЕКУЩАЯ

Цель: устранить известные баги, очистить код, подготовить к расширению модели.

### 3.1 Критические баги
- [ ] **Newton divergence при wasted trial + скважины** — `ReverseState()` не откатывает состояние скважины → NaN. Блокирует Buckley–Leverett симуляцию. См. [[Newton divergence при закачке воды через скважину]]
- [ ] **CPR diverges при Sw=0** — текущий обход: Sw_init=0.001. Нужна корректная обработка нулевой водонасыщенности (регуляризация или проверка на нулевой блок в ILU)

### 3.2 Рефакторинг
- [ ] Удалить `Shared0/` (дубль `Utils/`)
- [ ] Заменить `wstring` → `string` в ядре (убрать Windows-зависимость)
- [ ] Разбить `ReservoirSimulator` (~1361 строк) — выделить чистый solver API
- [ ] Убрать заглушенные DB-фабрики, ввести файловый ввод (JSON или YAML)

### 3.3 Тестовое покрытие
- [ ] Buckley–Leverett: симуляция vs аналитический профиль (после фикса Newton)
- [ ] PI-контроллер: интеграционные тесты на нестационарных задачах (well switching, breakthrough)
- [ ] Regression-тест на производительность (51×51×4, допустимая просадка ≤ 10%)
- [ ] Покрытие `ReservoirSimulator` — сейчас только через smoke/five-spot/visual

### Критерий завершения
Все тесты проходят (включая разблокированный `[.wells]`), `ReservoirSimulator` < 800 строк, нет зависимости от `wstring`.

## Фаза 4: Расширение модели скважин

Цель: полноценная модель скважин для реалистичных задач.

### 4.1 Режим BHP
- [ ] Фиксированное забойное давление (сейчас только дебит)
- [ ] Переключение дебит ↔ BHP по расписанию (через `WellScheduleBuilder`)
- [ ] Тесты: одна скважина BHP, five-spot с BHP, переключение режима mid-simulation

### 4.2 Модель Peaceman
- [ ] Productivity index (WI) с радиусом Писмана: WI = 2πkh / (ln(r_e/r_w) + S)
- [ ] Анизотропная поправка: r_0 = 0.28 √(√(ky/kx)Δx² + √(kx/ky)Δy²) / (⁴√(ky/kx) + ⁴√(kx/ky))
- [ ] Тесты: сравнение давления на забое с аналитикой, сетчатая сходимость WI

### 4.3 Закрытые границы
- [ ] No-flow BC без открытых граней
- [ ] Регуляризация давления: pin-pressure или средневзвешенное. См. [[закрытые границы требуют корректной регуляризации давления]]
- [ ] Тесты: замкнутый пласт с INJ+PROD, баланс масс, проверка что P не дрейфует

### Критерий завершения
Five-spot с BHP + Peaceman, закрытые границы, все тесты проходят. Сравнение с MRST для BHP-режима.

## Фаза 5: Расширение физики

Цель: приблизить модель к промышленным задачам.

### 5.1 Сжимаемость
- [ ] Слабая сжимаемость воды и нефти (линейная EOS: ρ = ρ_ref(1 + c_f(P - P_ref)))
- [ ] Сжимаемость породы (c_r): φ = φ_ref(1 + c_r(P - P_ref))
- [ ] Контроль: при c_f = c_r = 0 результаты совпадают с несжимаемым случаем

### 5.2 Капиллярное давление
- [ ] P_cow(S_w) — функция Леверетта или табличная
- [ ] Влияние на уравнение давления: P_o = P_w + P_cow
- [ ] Контроль: при P_cow = 0 результаты совпадают с текущей моделью

### 5.3 Гравитация
- [ ] Гравитационный член в уравнении потока: ∇·(λ_α ρ_α g ∇z)
- [ ] Важно для 3D задач с существенной разницей глубин
- [ ] Контроль: при горизонтальном пласте результаты не меняются

### Критерий завершения
Сжимаемость + капиллярка + гравитация, каждое расширение верифицировано на тестовых задачах с известным решением.

## Принципы развития

1. **Каждое расширение — отдельная фаза с изоляцией.** Не смешивать физику и рефакторинг.
2. **Backward compatibility по умолчанию.** Новый функционал при c=0 / отключённом параметре даёт прежний результат.
3. **Тест до кода.** Для каждого нового функционала сначала тест (хотя бы smoke), потом реализация.
4. **Визуальная верификация обязательна.** CSV + анимация, не только Catch2 assertions. См. [[feedback — visual verification always]]
5. **Профилирование при структурных изменениях.** Каждое изменение солвера — benchmark на 51×51×4.
6. **Один баг — одна заметка в `knowledge/debugging/`.** С описанием симптома, причины и фикса.
7. **Vault как единственный источник правды.** Roadmap, решения, баги — в vault, не в TODO-комментариях.
