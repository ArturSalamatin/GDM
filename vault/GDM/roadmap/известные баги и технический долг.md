## Критические баги

### BUG-001: Newton divergence при wasted trial + скважины
- **Симптом:** NaN в давлении/насыщенности при закачке воды через скважину на чистой нефти
- **Причина:** `ReverseState()` откатывает состояние ячеек, но не откатывает состояние скважины. При wasted trial (Newton не сошёлся) скважина помнит старые дебиты → NaN propagation
- **Воспроизведение:** тест `[.wells]` в test_buckley_leverett.cpp
- **Блокирует:** Buckley–Leverett симуляция vs аналитика, надёжность скважинного расчёта в целом
- **Статус:** 🔴 ОТКРЫТ
- **GitHub:** [#1](https://github.com/ArturSalamatin/GDM/issues/1)
- **Подробности:** [[Newton divergence при закачке воды через скважину]]

### BUG-003: `WellJobs::IsEmpty()` всегда возвращает false
- **Симптом:** скважина с пустыми данными перфораций не отсеивается, проходит дальше в симуляцию
- **Причина:** проверяется `!RawWellPerforationData.empty()` (весь вектор) вместо `!RawWellPerforationData[i].empty()` (элемент)
- **Файл:** `HydroSolver/Reservoir/Well/WellJobs.cpp:93-98`
- **Последствия:** UB при попытке построить перфорации из пустых данных
- **Статус:** 🔴 ОТКРЫТ
- **Подробности:** [[code-review-2026-06-28-баги-и-корректность]]

### BUG-004: `throw(string)` вместо `throw std::exception` в Wells.cpp
- **Симптом:** исключение при невычисленном дебите скважины утекает мимо всех `catch(std::exception&)`
- **Причина:** `throw("text" + ...)` выбрасывает `std::string`, не наследник `std::exception`
- **Файл:** `HydroSolver/Reservoir/Well/Wells.cpp:41`
- **Статус:** 🔴 ОТКРЫТ
- **Подробности:** [[code-review-2026-06-28-баги-и-корректность]]

### BUG-005: `LoadFlowFieldFromFile_bin` хардкодит `nz = 4`
- **Симптом:** некорректное чтение бинарного файла при числе слоёв ≠ 4
- **Причина:** `int nz = 4;// grid_dim[2]` — закомментированный код
- **Файл:** `HydroSolver/Reservoir/ReservoirSimulator.cpp:747`
- **Статус:** 🔴 ОТКРЫТ
- **Подробности:** [[code-review-2026-06-28-баги-и-корректность]]

### BUG-006: `Solve()` всегда возвращает `converged = true`
- **Симптом:** информация о расхождении линейного солвера теряется; Newton loop не знает, что AMG не сошёлся
- **Причина:** `return { iters, error, true }` — третий элемент захардкожен
- **Файл:** `HydroSolver/Solver/Math/LinearProblem.cpp:143`
- **Статус:** 🔴 ОТКРЫТ
- **Подробности:** [[code-review-2026-06-28-числовая-устойчивость]]

### BUG-007: Деление на ноль в гармоническом среднем подвижности
- **Симптом:** NaN в матрице Якобиана, если обе соседние ячейки имеют нулевую подвижность
- **Причина:** `denom = MobilityCell + MobilityNeighbour`, без проверки на ноль
- **Файл:** `HydroSolver/Reservoir/ReservoirSimulator.cpp:579-581`
- **Связь:** [[zero pivot в ILU0 при скалярном CPR на двухфазном Якобиане]] (BUG-002)
- **Статус:** 🔴 ОТКРЫТ
- **Подробности:** [[code-review-2026-06-28-числовая-устойчивость]]

### BUG-008: Деление на ноль в `SetRefWellPressure` при нулевой подвижности
- **Симптом:** `P_well = inf` → NaN каскадом
- **Причина:** `denom = Σ factor[l] * OverallMobility(l)`, при OverallMobility=0 для всех перфораций → деление на ноль
- **Файл:** `HydroSolver/Reservoir/Well/Wells.cpp:79-91`
- **Связь:** [[Newton divergence при закачке воды через скважину]] (BUG-001)
- **Статус:** 🔴 ОТКРЫТ
- **Подробности:** [[code-review-2026-06-28-числовая-устойчивость]]

### BUG-009: Фильтр `ActiveCells` не работает — `size_t + 1 > 0` всегда true
- **Симптом:** неактивные ячейки не фильтруются при привязке скважины к сетке
- **Причина:** `cellIdx` — `size_t` (unsigned), `cellIdx+1 > 0` тождественно истинно
- **Файл:** `HydroSolver/Reservoir/ReservoirSimulator.cpp:142`
- **Статус:** 🔴 ОТКРЫТ
- **Подробности:** [[code-review-2026-06-28-баги-и-корректность]]

### BUG-010: `const_cast` на `AccumulatedPerforations` в конструкторе `SomeWell`
- **Симптом:** потенциальный UB — мутация объекта, полученного по const-ссылке
- **Причина:** `const_cast<set_of_points::AccumulatedPerforations&>(perfs).AveragePerforationsOut(...)` обходит const
- **Файл:** `HydroSolver/Reservoir/Well/SomeWell.cpp:143`
- **Статус:** 🟡 ПОТЕНЦИАЛЬНЫЙ

### BUG-002: CPR diverges при Sw=0
- **Симптом:** солвер не сходится при нулевой начальной водонасыщенности
- **Причина:** нулевой блок в матрице Якобиана → zero pivot в ILU0 (fallback D[i]=1 недостаточен)
- **Обход:** Sw_init = 0.001 вместо 0.0
- **Статус:** 🟡 ОБХОД ЕСТЬ
- **Подробности:** [[zero pivot в ILU0 при скалярном CPR на двухфазном Якобиане]]

## Технический долг

### DEBT-002: wstring в ядре
- **Описание:** часть ядра использует `std::wstring` (наследие Windows GUI)
- **Риск:** невозможность сборки под Linux, усложнение интерфейсов
- **Действие:** заменить на `std::string` (UTF-8)
- **Приоритет:** средний (блокирует кроссплатформенность)

### DEBT-003: ReservoirSimulator — монолит ~1361 строк
- **Описание:** один класс содержит Newton loop, time stepping, assembly, solve, boundary conditions
- **Риск:** любое изменение в одном аспекте затрагивает весь файл, сложно тестировать изолированно
- **Действие:** выделить: TimeIntegrator, NewtonSolver, BoundaryConditions, SolverFacade
- **Приоритет:** высокий (блокирует unit-тестирование ядра)

### DEBT-004: DB-фабрики заглушены
- **Описание:** `ConnectionFactory`, `ReservoirFactory`, `HorizonFactory`, `WellFactory`, `RawWellFactory` — пустые заглушки после отключения PostgreSQL
- **Риск:** мёртвый код, путаница
- **Действие:** удалить при переходе на файловый ввод (фаза 7)
- **Приоритет:** низкий (не мешает)

### DEBT-005: UniversalSVParser/Writer исключены из сборки
- **Описание:** cp1251 кодировка несовместима с `/utf-8`. Файлы есть, но не компилируются
- **Действие:** переписать на UTF-8 или удалить, если файловый ввод пойдёт через JSON
- **Приоритет:** низкий

### DEBT-006: PI-контроллер выключен по умолчанию
- **Описание:** реализован и имеет 10 юнит-тестов, но `use_pi_controller_ = false`
- **Причина:** не верифицирован на нестационарных задачах (breakthrough, well switching)
- **Действие:** верифицировать → включить
- **Приоритет:** средний
- **Подробности:** [[PI-контроллер safety=1 и target=12 для Newton-based timestep control]]

### DEBT-007: AMGCL — локальная копия вместо FetchContent
- **Описание:** библиотека AMGCL (header-only, MIT) хранится как локальная копия в `HydroSolver/AMGSolver/amgcl/`. Репозиторий upstream: `https://github.com/ddemidov/amgcl`
- **Локальные изменения:** один файл — `amgcl/relaxation/ilu0.hpp`, строки 156–157. Оригинал: `precondition(!math::is_zero((*D)[i]), "Zero pivot in ILU")` — exception при zero pivot. Наша правка: `if (math::is_zero((*D)[i])) (*D)[i] = static_cast<value_type>(1)` — fallback вместо exception (BUG-002 workaround)
- **Также:** версия 2022 vs legacy 2020 — добавлены `col_type`/`ptr_type` typedefs, zero-stripping в L/U, `static_cast<ptrdiff_t>` в циклах, допуск параметра `k` в params
- **Риск:** устаревшая версия, невозможность обновления без ручного merge, патч не документирован
- **Действие:** перейти на `FetchContent`, наш патч вынести в отдельный `.patch` файл или wrapper. Прямые изменения amgcl запрещены
- **Приоритет:** средний (блокирует обновление amgcl)
- **Подробности:** [[локальные патчи AMGCL для GDM]]

### DEBT-008: Eigen — локальная зависимость без версионирования
- **Описание:** `Maps.h` включает `<Eigen/Eigen>` как системную зависимость. Eigen не управляется CMake (нет `find_package`, нет `FetchContent`). Используется только в legacy-таргете `gdm_data`
- **Репозиторий upstream:** `https://gitlab.com/libeigen/eigen` (GitLab, MPL2)
- **Риск:** сборка зависит от того, установлен ли Eigen на машине; версия не зафиксирована
- **Действие:** подключить через `FetchContent` из GitLab. Если `gdm_data` будет удалён — зависимость исчезнет
- **Приоритет:** низкий (Eigen используется только в legacy-таргете)

### DEBT-009: test*.txt — отладочный дамп в cwd
- **Описание:** код в `MER_Descriptor.cpp`, `MatrixCSR.cpp`, `LinearProblem.cpp`, `SparsityPattern.cpp`, `AbstractGrid.h` пишет отладочные файлы `test_*.txt` в текущую рабочую директорию
- **Файлы:** `test_MER_*.txt`, `test_connections.txt`, `test_Matrix.txt`, `test_diagValues.txt`, `test_SparsityPattern*.txt`, `test_RHS.txt`, `test_Corrections.txt`
- **Контроль версий:** файлы в `.gitignore` — не отслеживаются ✅
- **Проблема:** засоряют корень проекта и `build/`; пути не настраиваемые; дамп включён в production-коде (нет `#ifdef DEBUG`)
- **Действие:** обернуть в `#ifdef GDM_DUMP_DEBUG` или вынести за флаг; если оставлять — писать в `build/debug_dump/`
- **Приоритет:** низкий

### DEBT-010: `new`/`delete` для скважин вместо `unique_ptr`
- **Описание:** `std::map<WellName, wells::SomeWell*>` с ручным `new` при вставке и `delete` в деструкторе
- **Риск:** утечка памяти при исключении между `new` и `insert`; отсутствие move-семантики
- **Действие:** заменить на `std::map<WellName, std::unique_ptr<wells::SomeWell>>`
- **Файл:** `ReservoirSimulator.cpp:145-156`
- **Приоритет:** средний
- **Подробности:** [[code-review-2026-06-28-утечки-ресурсов-и-память]]

### DEBT-011: `static` PVT-свойства в `PhysPropCell`
- **Описание:** `static std::array<double, 8> ConstantPointProperties` — все ячейки разделяют один набор PVT-констант
- **Риск:** невозможность запуска параллельных симуляций; race condition при OpenMP; неявная глобальная зависимость
- **Действие:** передавать PVT через конструктор или shared-контекст (не static)
- **Файл:** `AbstractCells.h:148`, `AbstractCells.cpp:7`
- **Приоритет:** средний (блокирует OpenMP и мульти-модельные расчёты)
- **Подробности:** [[code-review-2026-06-28-утечки-ресурсов-и-память]]

### DEBT-012: `vector` аллокация внутри тройного цикла в `AccountForBoundaryConditions`
- **Описание:** на каждой итерации по `(i,j,k)` создаётся `std::vector<double>(blockSize)` и `std::vector<double>(B)` через heap-аллокацию
- **Риск:** тысячи heap-аллокаций на Newton step (51×51×4 = ~400 граничных ячеек × 2 направления)
- **Действие:** заменить на `std::array<double, 4>` / `double[4]` (как в `fillMatrixBlockRow`)
- **Файл:** `ReservoirSImulator.h:145-146`
- **Приоритет:** средний (производительность)
- **Подробности:** [[code-review-2026-06-28-утечки-ресурсов-и-память]]

### DEBT-013: `OverallFluxes()` — O(N) heap-аллокаций через вложенные `push_back`
- **Описание:** строит 4 трёхмерных `vector<vector<vector<double>>>` по-элементно, ~40K аллокаций для 51×51×4
- **Риск:** производительность; метод вызывается каждый шаг по времени
- **Действие:** предвыделять размеры; или хранить flux-поле как flat-array
- **Файл:** `ReservoirSimulator.cpp:794-1050`
- **Приоритет:** средний
- **Подробности:** [[code-review-2026-06-28-утечки-ресурсов-и-память]]

### DEBT-014: Дублирование ~450 строк логики потоков
- **Описание:** `OverallFluxes()`, `OilContourFlux()`, `WaterContourFlux()` содержат одинаковую структуру: тройной цикл, upstream-выбор, умножение на подвижность
- **Действие:** параметризовать обход граней, объединить в один шаблонный метод
- **Файл:** `ReservoirSimulator.cpp:794-1247`
- **Приоритет:** средний (связан с DEBT-003 рефакторингом ReservoirSimulator)
- **Подробности:** [[code-review-2026-06-28-архитектурные-ограничения]]

### DEBT-015: Все поля `ReservoirSimulator` — public
- **Описание:** `Grid`, `MyProblem`, `Wells`, accumulators, `RefPressure` — всё public
- **Риск:** любой клиент может сломать инвариант; API хрупкий
- **Действие:** выделить private members + публичные методы (часть DEBT-003)
- **Файл:** `ReservoirSImulator.h:39-72`
- **Приоритет:** средний
- **Подробности:** [[code-review-2026-06-28-архитектурные-ограничения]]

### DEBT-016: `B = 2` захардкожен в нескольких классах
- **Описание:** число уравнений на ячейку (`B = 2`) дублировано в `LinearProblem`, `ReservoirSimulator`, `SomeWell` как `static constexpr`/`const int`
- **Риск:** расширение до трёхфазной модели или добавление уравнения энергии потребует grep + замену
- **Действие:** единая constexpr-константа в общем заголовке или template-параметр
- **Приоритет:** низкий (до расширения модели)
- **Подробности:** [[code-review-2026-06-28-архитектурные-ограничения]]

### DEBT-017: `mutable` / `const_cast` вместо честной const-корректности
- **Описание:** `MER_Data` — 7+ `mutable` полей, `const` методы мутируют через `mutable`. `WellJobs::RawWellPerforationData` — `mutable`. `SomeWell` — `const_cast`
- **Риск:** thread-unsafe; `const` — фасад, не контракт; мешает параллелизации
- **Действие:** разделить на const-query и non-const-mutation; кэшированное состояние MER вынести в отдельный mutable-объект
- **Приоритет:** средний
- **Подробности:** [[code-review-2026-06-28-архитектурные-ограничения]]

### DEBT-018: Мёртвый код — ~200 строк закомментированного кода
- **Описание:** NeuralNetwork SaveWeights/LoadWeights (110 строк), IRAP/JSON/LogFile (70 строк), `if (false && ...)`, пустой `update_currentIntegrationTau`, некорректные закомментированные assert-ы
- **Действие:** удалить
- **Файлы:** `ReservoirSimulator.cpp:282-350, 1141, 1253-1361`, `NumericalParameters.h:105`, `AbstractCells.h:60-61, 82-83, 110-111`
- **Приоритет:** низкий
- **Подробности:** [[code-review-2026-06-28-мёртвый-код-и-гигиена]]

### DEBT-019: Magic numbers для индексации свойств ячейки
- **Описание:** свойства хранятся в `vector<double>` / `array<double>` с доступом по числовым индексам (`ConstantFieldProperties[7]` = PoreVolume, `DependentFieldProperties[3]` = F_Oil)
- **Риск:** при изменении порядка — молчаливая ошибка; accessor-методы скрывают проблему
- **Действие:** enum или именованная структура вместо индексов
- **Файл:** `TwoPhaseFlowCell.cpp`, `AbstractCells.h`
- **Приоритет:** низкий
- **Подробности:** [[code-review-2026-06-28-архитектурные-ограничения]]

### DEBT-020: Глубокая иерархия наследования ячеек (6 уровней)
- **Описание:** `SomeDimCell → Dim1Cell → Dim2Cell → Dim3Cell`, плюс множественное наследование `SomeProcessCell_TimeDependent<Dim3Cell>` от `Dim3Cell`, `TimeDependentCell`, `PhysPropCell`
- **Риск:** сложность, Dim1/Dim2 никогда не инстанцируются; можно заменить одной структурой
- **Действие:** collapsed cell hierarchy
- **Приоритет:** низкий
- **Подробности:** [[code-review-2026-06-28-архитектурные-ограничения]]
