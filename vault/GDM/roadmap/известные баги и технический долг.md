## Критические баги

### BUG-001: SIGSEGV при закачке воды — out-of-bounds в AddFlowFieldSnapShot при ny=1
- **Симптом:** SIGSEGV (access violation) после первого успешного временного шага при сетке с ny=1
- **Причина:** `OverallFluxes()` не заполняет `j_Y` при `ny <= 1`, но `AddFlowFieldSnapShot()` безусловно обращается к `j_Y[k]` → out-of-bounds. Исходный диагноз (NaN в SetRefWellPressure) **опровергнут** — Newton сходится нормально
- **Воспроизведение:** тест `[.wells]` в test_buckley_leverett.cpp (сетка 10×1×1)
- **Блокирует:** Buckley–Leverett симуляция vs аналитика, любые сценарии с ny=1 или nx=1
- **Статус:** ✅ ИСПРАВЛЕНО 2026-06-28
- **GitHub:** [#1](https://github.com/ArturSalamatin/GDM/issues/1)
- **План:** [[bug-001 well-state-rollback]]
- **Ветка:** fix/bug-001/well-state-rollback
- **Подробности:** [[Newton divergence при закачке воды через скважину]]

### BUG-003: `WellJobs::IsEmpty()` всегда возвращает false
- **Симптом:** скважина с пустыми данными перфораций не отсеивается, проходит дальше в симуляцию
- **Причина:** проверяется `!RawWellPerforationData.empty()` (весь вектор) вместо `!RawWellPerforationData[i].empty()` (элемент)
- **Файл:** `HydroSolver/Reservoir/Well/WellJobs.cpp:93-98`
- **Последствия:** UB при попытке построить перфорации из пустых данных
- **Статус:** 🔴 ОТКРЫТ
- **Подробности:** [[code-review-2026-06-28-баги-и-корректность]]

### BUG-004: `throw(string)` вместо `throw std::exception` в Wells.cpp

### BUG-006: `Solve()` всегда возвращает `converged = true`

### BUG-011: `ConvertTriple2Local` молча превращает −1 в огромный `size_t`
- **Симптом:** при обращении к неактивной ячейке через `(i,j,k)` вместо ошибки возвращается ~2⁶³ — индекс за пределами массива
- **Причина:** `ConvertGlobal2Local()` возвращает `long int` (−1 для неактивных), но `ConvertTriple2Local()` объявлен как `size_t` — неявное приведение −1 → `SIZE_MAX`
- **Файл:** `HydroSolver/Solver/Grids/AbstractGrid.h:182-184`
- **Статус:** 🔴 ОТКРЫТ

### BUG-012: Несовпадение типов при бинарной записи/чтении `grid_dim`
- **Симптом:** при чтении `LoadFlowFieldFromFile_bin` данные повреждаются — grid_dim, nx, ny содержат мусор
- **Причина:** запись: `vector<size_t>` (8 байт × 3 = 24 байта на x64). Чтение: `array<int, 3>` (4 байта × 3 = 12 байт). Считанные значения содержат половину первого `size_t` вместо трёх измерений
- **Файл:** `ReservoirSimulator.cpp:681` (write) vs `ReservoirSimulator.cpp:745-746` (read)
- **GitHub:** [#2](https://github.com/ArturSalamatin/GDM/issues/2)
- **План:** [[bug-012 binary-grid-dim-type-mismatch]]
- **Ветка:** fix/bug-012/binary-grid-dim-type-mismatch
- **Статус:** ✅ исправлено 2026-06-28

### BUG-013: `SparsityPattern` конструктор — аргументы `vector<bool>` перепутаны
- **Симптом:** blockPattern содержит 1 элемент вместо `eqNmbr² = 4`, CRS-структура некорректна
- **Причина:** `std::vector<bool>(true, eqNmbr_ * eqNmbr_)` — `true` → `size=1`, второй аргумент = `value`. Правильно: `(eqNmbr_ * eqNmbr_, true)`
- **Файл:** `HydroSolver/Solver/Math/SparsityPattern.cpp:166`
- **Статус:** 🔴 ОТКРЫТ (может не вызываться в production, но при использовании — повреждение матрицы)

### BUG-014: `CacheFile::operator()` — отсутствует `return` в else-ветке
- **Симптом:** UB — функция возвращает `T&`, но не имеет `return` когда `pos + size - 1 >= current_end`
- **Причина:** else-блоки (строки 51-58) пустые, нет `return` и нет `throw`
- **Файл:** `HydroSolver/Temp/CacheFile.h:44-59`
- **Статус:** 🟡 ПОТЕНЦИАЛЬНЫЙ (класс может не использоваться в production)

### BUG-015: `std::vector<bool>` под OpenMP — data race
- **Симптом:** потенциальное повреждение данных при параллельной записи в вектор сходимости
- **Причина:** `std::vector<bool>` использует bit-packing — запись в разные элементы одного байта = race condition. `vector<char>` или `vector<int>` безопасны
- **Файл:** `ReservoirSimulator.cpp:459,462`
- **Статус:** 🔴 ОТКРЫТ

### BUG-016: Утечка памяти — `new char[]` без `delete[]` в WellDataHandler
- **Симптом:** `char* var = new char[sizes[j]]` выделяется в цикле, но нигде не освобождается
- **Причина:** отсутствует `delete[] var` после использования
- **Файл:** `HydroSolver/Utils/WellDataHandler.cpp:43`
- **Статус:** 🔴 ОТКРЫТ

### BUG-017: `generate_temporal_grid` — деление на ноль при `frames ≤ 1`
- **Симптом:** при `frames = 1` → деление на ноль; при `frames = 0` → underflow `size_t` → деление на `SIZE_MAX`, цикл на миллиарды итераций
- **Причина:** `(end - start) / (frames - 1)` без проверки `frames`
- **Файл:** `HydroSolver/Reservoir/CalculationManager.cpp:46`
- **Статус:** 🟡 ПОТЕНЦИАЛЬНЫЙ (вызывается с `frames` из конфигурации)

### BUG-018: `snprintf` с `%u` для `size_t` — UB на x64
- **Симптом:** grid dimensions выводятся как мусор на x64, где `size_t` = 8 байт, а `%u` ожидает 4 байта
- **Причина:** `snprintf(..., "%u;%u;%u;%u", grid_size.Nx, grid_size.Ny, ...)` — `Nx`/`Ny`/`Nz` = `size_t`, формат `%u` = `unsigned int`. На x64 аргументы сдвигаются
- **Файл:** `DataPrinter.h:54`, `RawHorizon.h:43`
- **Статус:** 🔴 ОТКРЫТ
- **Действие:** `%u` → `%zu` или использовать `std::format` / `std::to_string`

### BUG-002: CPR zero pivot — три проявления
- **Симптом:** солвер не сходится или abort() в Debug при определённых конфигурациях сетки/насыщенности
- **Проявление 1 (ILU0):** zero pivot в `ilu0.hpp:156` при тонкой сетке (41×41) даже при Sw=0.2 — elimination обнуляет pivot. Обход: fallback `D[i]=1` (наш патч в ilu0.hpp)
- **Проявление 2 (CPR block inversion):** при Sw=0 вся Sw-строка Якобиана нулевая → CPR 2×2 block inversion singular → NaN → GMRES diverges. Обход: Sw_init ≥ 0.001
- **Проявление 3 (CPR block-LU, `cpr.hpp:522`):** `assert(!math::is_zero(d))` в LU-факторизации B×B блока внутри CPR. Падает в обоих конфигах (Release и Debug) — abort(). Тест: `Grid convergence: single injector` (278/279 passed, 1 failed). Обнаружено 2026-06-29 при верификации BUG-001. Не покрывается патчем ilu0.hpp
- **Причина (общая):** near-singular или singular блоки Якобиана при определённых Sw → zero pivot на разных уровнях CPR-прекондиционера (ILU0, block inversion, block-LU)
- **Обход:** Sw_init = 0.001 вместо 0.0 (не устраняет проявление 3)
- **Статус:** ✅ ИСПРАВЛЕНО 2026-06-29 — все три проявления покрыты (ilu0 fallback, Sw_init ≥ 0.001, cpr.hpp fallback). Near-zero pivot → FEAT-010
- **GitHub:** [#4](https://github.com/ArturSalamatin/GDM/issues/4)
- **Ветка:** fix/bug-002/cpr-zero-pivot
- **План:** [[bug-002 cpr-zero-pivot]]
- **Подробности:** [[zero pivot в ILU0 при скалярном CPR на двухфазном Якобиане]]

## Технический долг

### DEBT-002: wstring в ядре
- **Описание:** часть ядра использует `std::wstring` (наследие Windows GUI)
- **Риск:** невозможность сборки под Linux, усложнение интерфейсов
- **Действие:** заменить на `std::string` (UTF-8)
- **Приоритет:** средний (блокирует кроссплатформенность)

### DEBT-003: ReservoirSimulator — монолит ~1361 строк
- **Описание:** один класс содержит Newton loop, time stepping, assembly, solve, boundary conditions
- **Риск:** любое изменение в одном аспекте затрагивает весь файл, сложно тестировать изолированно
- **Действие:** выделить: TimeIntegrator, NewtonSolver, BoundaryConditions, SolverFacade
- **Приоритет:** высокий (блокирует unit-тестирование ядра)

### DEBT-004: DB-фабрики заглушены
- **Описание:** `ConnectionFactory`, `ReservoirFactory`, `HorizonFactory`, `WellFactory`, `RawWellFactory` — пустые заглушки после отключения PostgreSQL
- **Риск:** мёртвый код, путаница
- **Действие:** удалить при переходе на файловый ввод (фаза 7)
- **Приоритет:** низкий (не мешает)

### DEBT-005: UniversalSVParser/Writer исключены из сборки
- **Описание:** cp1251 кодировка несовместима с `/utf-8`. Файлы есть, но не компилируются
- **Действие:** переписать на UTF-8 или удалить, если файловый ввод пойдёт через JSON
- **Приоритет:** низкий

### DEBT-006: PI-контроллер выключен по умолчанию
- **Описание:** реализован и имеет 10 юнит-тестов, но `use_pi_controller_ = false`
- **Причина:** не верифицирован на нестационарных задачах (breakthrough, well switching)
- **Действие:** верифицировать → включить
- **Приоритет:** средний
- **Подробности:** [[PI-контроллер safety=1 и target=12 для Newton-based timestep control]]

### DEBT-007: AMGCL — локальная копия вместо FetchContent
- **Описание:** библиотека AMGCL (header-only, MIT) хранится как локальная копия в `HydroSolver/AMGSolver/amgcl/`. Репозиторий upstream: `https://github.com/ddemidov/amgcl`
- **Локальные изменения:** два файла: (1) `amgcl/relaxation/ilu0.hpp:156-157` — `precondition(!math::is_zero((*D)[i]), "Zero pivot in ILU")` заменён на fallback `(*D)[i] = 1` (BUG-002 проявление 1); (2) `amgcl/preconditioner/cpr.hpp:522-523` — `assert(!math::is_zero(d))` заменён на fallback `d = 1` + запись в массив (BUG-002 проявление 3)
- **Также:** версия 2022 vs legacy 2020 — добавлены `col_type`/`ptr_type` typedefs, zero-stripping в L/U, `static_cast<ptrdiff_t>` в циклах, допуск параметра `k` в params
- **Риск:** устаревшая версия, невозможность обновления без ручного merge, патч не документирован
- **Действие:** перейти на `FetchContent`, наш патч вынести в отдельный `.patch` файл или wrapper. Прямые изменения amgcl запрещены
- **Приоритет:** средний (блокирует обновление amgcl)
- **Подробности:** [[локальные патчи AMGCL для GDM]]

### DEBT-008: Eigen — локальная зависимость без версионирования
- **Описание:** `Maps.h` включает `<Eigen/Eigen>` как системную зависимость. Eigen не управляется CMake (нет `find_package`, нет `FetchContent`). Используется только в legacy-таргете `gdm_data`
- **Репозиторий upstream:** `https://gitlab.com/libeigen/eigen` (GitLab, MPL2)
- **Риск:** сборка зависит от того, установлен ли Eigen на машине; версия не зафиксирована
- **Действие:** подключить через `FetchContent` из GitLab. Если `gdm_data` будет удалён — зависимость исчезнет
- **Приоритет:** низкий (Eigen используется только в legacy-таргете)

### DEBT-009: test*.txt — отладочный дамп в cwd

### DEBT-047: `update_isSuccesfullNewtonTrial` побочно инкрементирует Newton counter
- **Описание:** метод `NumericalParameters::update_isSuccesfullNewtonTrial(bool f)` помимо установки `isSuccessfulTrial` безусловно вызывает `update_currentNewtonIterationCount()`, который делает `++currentNewtonIterationCount`. Это побочный эффект: семантически метод устанавливает флаг успешности, но фактически также считает итерации. Из-за этого `PerformNewtonLoop` стартует с `currentNewtonIterationCount = 1` вместо 0 — первый вызов `update_isSuccesfullNewtonTrial(false)` (инициализация) уже инкрементирует counter, несмотря на то что `set_currentNewtonIterationCount(0)` вызван строкой выше
- **Цепочка вызовов:**
  1. `PerformNewtonLoop()` (`ReservoirSimulator.cpp:435`): `set_currentNewtonIterationCount(0)` → counter = 0
  2. `PerformNewtonLoop()` (`ReservoirSimulator.cpp:436`): `update_isSuccesfullNewtonTrial(false)` → `isSuccessfulTrial = false; ++currentNewtonIterationCount` → counter = 1
  3. Newton loop начинает с counter = 1 вместо 0
  4. `IsNewtonIterationContinue()` проверяет `counter < maxNewtonIterNmbr(=12)` → доступно 11 итераций вместо 12
- **Проявление:** Newton loop делает на 1 итерацию меньше, чем задано в `maxNewtonIterNmbr`. При `maxNewtonIterNmbr = 12` доступно 11. Для текущих задач разница не критична — Newton сходится за 1–3 итерации (после фикса BUG-006)
- **Риск:** при сложных задачах потеря одной итерации может привести к ложному wasted trial. При `maxNewtonIterNmbr = 1` (edge case) Newton loop не сделает ни одной итерации
- **Причина:** нарушение Single Responsibility — `update_isSuccesfullNewtonTrial` делает две вещи: (1) устанавливает флаг, (2) считает итерации. Эти действия должны быть разделены
- **Файл:** `HydroSolver/Reservoir/NumericalParameters.h:108`
- **Код:** `void update_isSuccesfullNewtonTrial(bool f) { isSuccessfulTrial = f && CurrentANG_IsAccuracyReached(); update_currentNewtonIterationCount(); }`
- **Действие:** разделить на две операции. Убрать `update_currentNewtonIterationCount()` из `update_isSuccesfullNewtonTrial`, вызывать инкремент явно в Newton loop после `SingleIteration`. Или переименовать метод в `advanceNewtonIteration(bool converged)` и задокументировать оба эффекта. Предпочтительнее первый вариант (разделение), но требует проверки всех call sites
- **Приоритет:** низкий (после BUG-006 Newton делает 1–3 итерации, потеря одной не критична)
- **Связано с:** [[bug-006 solve-converged-always-true]]
- **Обнаружено при анализе:** BUG-006
- **Статус:** 🔴 ОТКРЫТ
