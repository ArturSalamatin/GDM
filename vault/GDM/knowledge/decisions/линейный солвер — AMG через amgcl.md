# Линейный солвер — AMG через amgcl

## Решение

В предыдущей реализации для решения блочной СЛАУ использовался **итерационный алгебраический многосеточный метод (AMG)** через библиотеку **amgcl** (Д. Демидов).

## Детали реализации

Модуль `linear_problem` (пространство имён `linear_problem`):

- `SparsityPattern` — шаблон разреженности блочной матрицы; `blockPattern` задаёт ненулевые элементы внутри блока $B \times B$
- `MatrixCSR` — хранение коэффициентов в CRS-формате; заполнение через `AddDiagBlock(l, data)` и `AddOffDiagBlock(l, neibIdx, data)`
- `LinearProblem` — интерфейс решения СЛАУ

Типы из amgcl:
- `value_type = amgcl::static_matrix<double, B, B>` — блок матрицы
- `rhs_type = amgcl::static_matrix<double, B, 1>` — блок правой части
- `BBackend = amgcl::backend::builtin<value_type>`

## Стек библиотек предыдущей реализации

- **amgcl** — линейный солвер (AMG)
- **pqxx** — связь с PostgreSQL (загрузка ФЭС месторождения)
- **GEOS** — геометрические операции (локализация целиков)

## Открытый вопрос для GDM

Сохраняем ли amgcl или переходим на другую библиотеку (Eigen, PETSc, Trilinos)? amgcl — header-only C++, хорошо интегрируется, поддерживает блочные матрицы. Аргументов за замену пока нет.
