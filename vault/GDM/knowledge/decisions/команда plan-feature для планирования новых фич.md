# Команда /plan-feature для планирования новых фич

## Назначение

Построение детализированного плана реализации новой функциональной возможности, готового к автономной реализации.

## Расположение

`.claude/commands/plan-feature.md`

## Аргумент

`FEAT-NNN` или номер GitHub issue.

## Отличие от /plan-fix и /plan-improve

| | /plan-fix | /plan-improve | /plan-feature |
|---|---|---|---|
| Что | сломано | работает, но плохо | ещё не существует |
| Отправная точка | воспроизвести баг | зафиксировать baseline | спроектировать API |
| Ключевой вопрос | почему ломается? | как улучшить не сломав? | как добавить не сломав? |
| Инвариант | тест красный→зелёный | тесты зелёные на каждом шаге | backward compatibility + новые тесты |
| Тесты | воспроизводитель + regression | regression + smoke | unit + integration + аналитика + visual |
| Физика/математика | цепочка причин | не применимо обычно | уравнения, размерности, ссылки |

## Фазы работы

1. **Сбор контекста** — vault-запись из [[планируемые фичи]], roadmap, связанные заметки, исследование точек интеграции
2. **Проектирование** — уравнения, API, backward compatibility, варианты архитектуры
3. **Детализация** — пошаговый план: API → реализация → тесты → интеграция → верификация
4. **Верификация** — 3 раунда: полнота, корректность, автономность
5. **Сохранение** — файл в `vault/GDM/plans/`, обратные ссылки

## Ключевые принципы

- **Backward compatibility:** при отключённом/нулевом параметре поведение идентично текущему
- **Физическое обоснование:** уравнения, ссылки на литературу, размерный анализ
- **Инкрементальность:** после каждого шага проект компилируется и все тесты зелёные
- **Верификация vs аналитика:** если есть аналитическое решение — сравнить
