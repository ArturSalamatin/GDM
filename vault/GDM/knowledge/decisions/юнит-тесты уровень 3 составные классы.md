# Юнит-тесты: уровень 3 — составные классы

Классы этого уровня зависят от нескольких предыдущих уровней. Их тестирование требует создания реалистичных (но маленьких) объектов: CRS-структур, ячеек с физическими свойствами, набора перфораций.

Связано: [[граф зависимостей классов gdm_core]], [[юнит-тесты уровень 2 средняя глубина зависимостей]]

## 1. MatrixCSR

**Файл:** `Solver/Math/MatrixCSR.h`, `Solver/Math/MatrixCSR.cpp`

**Пространство имён:** `reservoir_simulator::linear_problem`

**Зависимости:**
- Уровень 2: `CRSStructure` (через unique_ptr)

**Описание:** CRS-матрица с блочной структурой. Хранит значения (`value`), владеет `CRSStructure`. Методы для добавления диагональных и внедиагональных блоков по индексу ячейки.

**Что тестировать:**

### Конструктор
- `MatrixCSR(Layout::InterleavedPSw, 2, 3, graph, pattern)` — 3 ячейки, 2 уравнения
- `Row()`, `Col()` — совпадают с `CRSStructure`
- `Val()` — инициализирован нулями, размер = nnz

### AddDiagBlock
- Задать 2×2 диагональный блок ячейки 0: `{a00, a01, a10, a11}`
- Проверить: значения в `Val()` по индексам `DiagBlocks()[0..3]` == заданные
- Перезапись: повторный `AddDiagBlock` с другими данными → обновляются

### AddOffDiagBlock
- Задать внедиагональный блок между ячейками 0 и 1
- Проверить: значения по индексам `OffDiagBlocks()` == заданные

### ResetMatrix
- После AddDiagBlock + AddOffDiagBlock → `ResetMatrix()` → все `Val()` == 0

### Перегрузки const double*
- `AddDiagBlock(l, ptr)` и `AddOffDiagBlock(l, idx, ptr)` — те же результаты, что и с vector

### PrintCRS / PrintDiagBlocks
- Не падают (smoke-test)

**Пример графа для тестов:**
```cpp
// 3 ячейки: 0↔1, 1↔2
std::vector<std::vector<int>> graph = {{1}, {0, 2}, {1}};
std::vector<bool> pattern = {true, true, true, true};
MatrixCSR mat(Layout::InterleavedPSw, 2, 3, graph, pattern);

// диагональный блок ячейки 0
std::vector<double> diag = {1.0, 0.1, 0.2, 2.0};
mat.AddDiagBlock(0, diag);
// проверить Val() по позициям DiagBlocks
```

## 2. TwoPhaseFlowCell

**Файл:** `Solver/Grids/Cells/TwoPhaseFlowCell.h`, `Solver/Grids/Cells/TwoPhaseFlowCell.cpp`

**Пространство имён:** `reservoir_simulator::cell`

**Зависимости:**
- Уровень 2: `SomeProcessCell_TimeDependent<Dim3Cell>` (AbstractCells.h)
- Статические данные: `PhysPropCell::ConstantPointProperties` (вязкости, плотности, g, сжимаемости)

**Описание:** Ячейка двухфазного потока. Хранит: `ConstantFieldProperties` = {porosity, permeability, res_oil_sat, res_water_sat, ...}, `VariableFieldProperties` = {S_water, P}. Вычисляет: DependentFieldProperties = {density_oil, density_water, mobility_overall, F_oil, F_water, mass_oil, mass_water, derivatives...}.

**Предусловие:** Перед созданием ячейки нужно вызвать `PhysPropCell::set_constantPointProperties({visc_oil, visc_water, rho_oil, rho_water, g, compress_oil, compress_water, P_ref})`.

**Что тестировать:**

### Статические свойства (Corey relperm)
- `RelativePermeabilityOil(S_w)`: при `S_w = S_wr` → `k_ro = 1`, при `S_w = 1 - S_or` → `k_ro = 0`
- `RelativePermeabilityWater(S_w)`: при `S_w = S_wr` → `k_rw = 0`, при `S_w = 1 - S_or` → `k_rw = 1`
- Монотонность: `k_ro` убывает, `k_rw` возрастает с ростом `S_w`

### Mobility
- `MobilityOil() = k * k_ro / mu_o`
- `MobilityWater() = k * k_rw / mu_w`
- `MobilityOverall() = MobilityOil() + MobilityWater()`

### Fractional flow
- `F_Oil() = MobilityOil() / MobilityOverall()`
- `F_Water() = 1 - F_Oil()`
- Инвариант: `F_Oil() + F_Water() == 1` (с точностью до double)

### Density
- `DensityOil(P) = rho_0_oil * (1 + c_oil * (P - P_ref))`
- При несжимаемых (c=0): `DensityOil(P) == rho_0_oil` для любого P

### Mass
- `MassOil = Volume * porosity * S_oil * DensityOil`
- `MassWater = Volume * porosity * S_water * DensityWater`

### AcceptState / ReverseState / UpdateState
- Создать ячейку с S_w=0.3, P=1e5
- `AcceptState()`
- `UpdateState({0.1, 1e4})` → S_w=0.4, P=1.1e5
- `ReverseState()` → S_w=0.3, P=1e5

### ApplyPhysicalConstraints
- `S_w < 0` после UpdateState → обрезается до `S_wr`
- `S_w > 1 - S_or` → обрезается до `1 - S_or`

### Derivatives (для Newton)
- `DerivativeRelativePermeabilityOil` — числ. vs аналитическая (конечные разности)
- `DerivativeF_Oil` — dF_oil/dSw

**Подготовка:**
```cpp
// init static properties
std::array<double, 8> props = {
    1.0 / 86400.0 / 1000.0,  // visc_oil (Pa·day)
    1.0 / 86400.0 / 1000.0,  // visc_water
    800.0,  // rho_oil
    1000.0, // rho_water
    9.81,   // g
    0.0,    // compress_oil (incompressible)
    0.0,    // compress_water
    1e5     // P_ref
};
PhysPropCell::set_constantPointProperties(props);

// constFieldProp = {porosity, permeability, res_oil_sat, res_water_sat, ...}
// varFieldProp = {S_water, Pressure}
// center = {x, y, z}, size = {hx, hy, hz}
```

Замечание: точная структура `ConstantFieldProperties` (9 элементов) и `VariableFieldProperties` (2 элемента) определяется внутри `TwoPhaseFlowCell`. Нужно проверить порядок в конструкторе `OilField::MakeCell()` или в тест-хелперах проекта.

## 3. WellJobs

**Файл:** `Reservoir/Well/WellJobs.h`, `Reservoir/Well/WellJobs.cpp`

**Пространство имён:** `reservoir_simulator`

**Зависимости:**
- Уровень 0: `WellJobTime`, `Segment`
- Уровень 1: `SetOfPoints`
- Уровень 2: `AccumulatedPerforations`
- defines.h: `WellName`, `LayerAggregationTree`, `WellJobsPerLayer`

**Описание:** Агрегатор перфораций скважины по слоям. Принимает сырые данные о ГТМ (WellJobsData) и дерево агрегации слоёв, строит `WellJobsPerLayer`. Метод `AccumulatePerforations()` возвращает `PerforationsOfWell` (map<layer_id, AccumulatedPerforations>).

**Что тестировать:**

### Конструктор из WellJobsPerLayer (простой)
- `WellJobs(name, jobs_per_layer)` — 1 слой, 2 операции: open [10,30] t=100, close [20,30] t=200
- `Name()` == name
- `IsEmpty()` == false
- `jobsInLayer(0)` содержит 2 операции

### Конструктор из WellJobsData + LayerAggregationTree
- 2 слоя в сырых данных, дерево агрегации объединяет их в 1 слой
- Результат: `jobsInLayer(0)` содержит операции из обоих слоёв

### AccumulatePerforations
- 1 слой, open [0,100] t=0 → `PerforationsOfWell[0].getPerforations(50).TotalLength() == 100`
- 2 слоя: слой 0 open [0,50], слой 1 open [60,90] → каждый слой независим

### AccumulatePerforations с IsActiveCell filter
- `AccumulatePerforations(active_cells)` — неактивные ячейки удаляются из перфораций

### IsEmpty
- `WellJobs` без операций → `IsEmpty() == true`

### RemovePerfsAtInactiveCells
- Перфорации, попадающие на неактивные ячейки, удаляются

**Примерные тесты:**
```cpp
std::wstring name = L"WELL_1";
JobsInLayer jobs = {
    WellJobTime(10.0, 30.0, true, 100.0),
    WellJobTime(20.0, 30.0, false, 200.0)
};
WellJobs wj(name, jobs);
CHECK(wj.Name() == name);
CHECK_FALSE(wj.IsEmpty());

auto perfs = wj.AccumulatePerforations();
// на t=150: open [10,30], длина = 20
// на t=250: open [10,30] минус close [20,30] = [10,20], длина = 10
```

## Замечания по тестированию уровня 3

### TwoPhaseFlowCell — глобальное состояние
`PhysPropCell::ConstantPointProperties` — **статический массив**. Его нужно инициализировать один раз в тестовом файле или в секции `BEFORE_ALL`. Разные тесты TwoPhaseFlowCell не могут использовать разные значения вязкости параллельно.

### WellJobs — ссылка на имя
`WellJobs::ItsName` хранит **const reference** на `WellName`. Объект `WellName` должен жить дольше `WellJobs`. В тестах — хранить имя в переменной, не передавать временный объект.

### MatrixCSR — маленькие графы
Для тестов MatrixCSR достаточно графов из 2–4 ячеек. Не нужно создавать реальную сетку — только `vector<vector<int>>` связности.

## Порядок реализации

1. **MatrixCSR** — зависит только от CRSStructure, чистая линейная алгебра
2. **TwoPhaseFlowCell** — ключевой для физики, но требует setup статических свойств
3. **WellJobs** — скважинная логика, завершает покрытие модуля перфораций

## Уровень 4+ (не для юнит-тестов)

Классы уровня 4 и выше (`OilField`, `LinearProblem`, `SomeWell`, `ReservoirSimulator`) тестируются интеграционно — уже покрыты в:
- `test_smoke.cpp` — базовый запуск
- `test_components.cpp` — Corey relperm, fractional flow, CSR
- `test_mass_balance.cpp` — баланс масс
- `test_five_spot.cpp` — 5-скважинный тест
- `test_visual_verification.cpp` — визуальная верификация
- и др.

Юнит-тесты уровней 0–3 заполняют пробел: проверяют отдельные классы изолированно, без запуска полного симулятора.
