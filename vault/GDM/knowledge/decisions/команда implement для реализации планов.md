# Команда implement для реализации планов

## Решение

Создана команда `/implement <ID>`, замыкающая цикл автоматизации: `/issue` → `/plan-*` → `/implement`.

## Почему

Plan-команды создают самодостаточный план, но его исполнение требует дисциплины: последовательность шагов, сборка после каждого, частые коммиты, фиксация новых проблем, обновление vault. Без формализованной команды Claude может срезать углы — пропустить проверку, забыть обновить реестр, закоммитить сломанное состояние.

## Ключевые решения

1. **Одна команда на все типы.** План уже специализирован (plan-fix vs plan-feature), исполнение универсально.
2. **Частые коммиты.** Каждый коммит — компилируемое состояние с зелёными тестами. Если тесты падают — это явно задокументировано.
3. **Строгий скоуп.** Делать только то, что в плане. Найденные проблемы → inbox, не в код.
4. **Протокол отката.** Если реализация зашла в тупик — `git stash`, зафиксировать блокер, не коммитить сломанное.
5. **Vault-изменения отдельно.** Код и vault — разные коммиты.
