# 2026-06-27 — Система plan-команд и консистентность

## Что сделано

### Созданы 5 plan-команд
- `/plan-fix` — план исправления бага (BUG-NNN)
- `/plan-improve` — план рефакторинга/миграции (DEBT-NNN)
- `/plan-feature` — план новой фичи (FEAT-NNN)
- `/plan-validate` — план валидационного кейса (VAL-NNN)
- `/plan-research` — план численного эксперимента (RES-NNN)

Каждая команда: 5 фаз (сбор контекста → проектирование → детализация → верификация 3 раунда → сохранение). Результат — самодостаточный план в `vault/GDM/plans/`, готовый к автономной реализации без контекста.

### Обновлён `/issue`
- Поддержка всех 5 типов (BUG/DEBT/FEAT/VAL/RES)
- Режим existing + new mode

### Консистентность (4 раунда верификации, ~40 правок)

| Раунд | Метод | Найдено |
|---|---|---|
| 1 | Pattern-based grep по известным проблемам | 16 |
| 2 | Полное перечитывание всех 6 файлов | 9 |
| 3 | Матрица структурных элементов + grep неполных типов | 8 |
| 4 | Функциональный walkthrough (симуляция реальных вызовов) | 3 |

Основные категории правок:
- Неполные перечисления типов (BUG/FEAT → BUG/DEBT/FEAT/VAL/RES)
- Ленивые ссылки между командами («Аналогично /plan-fix» → самодостаточное описание)
- Отсутствие #N→ID резолюции при вызове по номеру issue
- Безусловные `gh issue comment` и «GitHub issue закрыт» (добавлено «если создан»)
- Пропущенные секции в plan-validate и plan-research (зона неприкосновенности, инвентаризация, тесты)

## Архитектура системы команд

Два набора команд с чётким разделением ответственности:

1. **`/issue`** — формирует контекст на GitHub: описание, анализ, предложения решения, имя ветки. Создаёт issue в репозитории.
2. **`/plan-*`** — создаёт детализированный план реализации в vault. Шаги, файлы, код, проверки, подводные камни. Готов к автономному исполнению.

Связь: `/issue` → GitHub issue → `/plan-*` → план в `vault/GDM/plans/`

## Решения

- BUG и DEBT — один реестр (`известные баги и технический долг.md`), разделять при >30 записей
- Удалён старый `/plan` (единый) → заменён 5 специализированными командами
- Каждая plan-команда самодостаточна (без ссылок «аналогично /plan-fix»)
