# Сессия 6a: Layout-абстракция для CRS-матрицы

## Контекст

Сессия 6 (CPR-прекондиционер) требует перестановки переменных: amgcl CPR жёстко использует `col % B == 0` для выбора «давления». Наш порядок `[Sw, P]` приводит к тому, что CPR берёт Sw вместо P.

Первоначальный план — runtime swap при передаче в CPR — был пересмотрен. Пользователь предложил архитектурный рефакторинг: вынести маппинг «физические индексы → CRS-позиции» в отдельный класс с параметром Layout.

## Результат

| Метрика | До | После |
|---|---|---|
| Тесты | 35 pass | 35 pass (773152 assertions) |
| Сборка | Release OK | Release OK |
| Layout | hardcoded interleaved | 3 layout через enum |

## Что сделано

### 1. Новый класс CRSStructure

Файлы: `HydroSolver/Solver/Math/CRSStructure.h`, `CRSStructure.cpp`

```cpp
enum class Layout : unsigned char {
    InterleavedSwP,  // [Sw0,P0, Sw1,P1, ...] — текущий
    InterleavedPSw,  // [P0,Sw0, P1,Sw1, ...] — для CPR
    Blocked          // [P0,...,PN, Sw0,...,SwN] — будущее
};
```

CRSStructure инкапсулирует:
- Построение `row_`, `col_`, `diagBlocks_`, `offDiagBlocks_`, `elementsAboveBlockRow_`
- Permutation tables: `permPhysicalToCRS_[B]`, `permCRSToPhysical_[B]`, `blockPermPhysicalToCRS_[B*B]`
- `GlobalIndex(cell, var)` — физический индекс → глобальная CRS-позиция
- `UnpackCorrections(cell, corrections, physical)` — обратный маппинг

Ключевой инвариант: `diagBlocks_` и `offDiagBlocks_` индексированы в **физическом** порядке блока, но указывают на CRS-позиции с учётом layout. Поэтому `CopyBlock(data[physIdx])` → `val[diagBlocks[offset + physIdx]]` работает без изменений при любом layout.

Для interleaved layouts CRS-строки строятся в CRS-порядке (внешний цикл по `crsRow`), а `diagBlocks_` заполняется через промежуточный буфер `diagTmp[]`, индексированный по `physRow * B + physCol`.

Blocked layout — заглушка (структурно иной, несовместим с блочным AMGCL backend).

### 2. MatrixCSR переведён на CRSStructure

- `unique_ptr<SparsityPattern> pattern` → `unique_ptr<CRSStructure> crs_`
- Forward declaration `class SparsityPattern` удалён из MatrixCSR.h
- Конструктор: `MatrixCSR(Layout, unsigned char eqNmbr, size_t cellNmbr, connectivity, blockPattern)`
- `Row()/Col()/DiagBlocks()/OffDiagBlocks()/EqNmbr()` делегируют к `crs_->`
- CopyBlock, AddDiagBlock, AddOffDiagBlock — без изменений (используют crs_->DiagBlocks() и т.д.)
- `GetCRS()` — публичный доступ к CRSStructure

### 3. LinearProblem принимает Layout

- Конструктор: `LinearProblem(Layout, absTol, relTol, connectivity, blockPattern)`
- `AddDiagBlock(l, data, dataRHS)` — rhs пишется через `crs.GlobalIndex(l, var)` вместо `l * B + i`
- Новые методы:
  - `GetCRS()` → `const CRSStructure&`
  - `UnpackCellCorrections(cell, physical[])` — распаковка corrections в физический порядок

### 4. UpdateGrid переписан

Было:
```cpp
Grid.UpdateState(MyProblem.Corrections(), B);
// ... convergence check через Corrections()[B*l + i]
```

Стало:
```cpp
double corr[B];
MyProblem.UnpackCellCorrections(l, corr);
Grid[l].UpdateState(corr);
// ... convergence check через corr[i]
```

Update и convergence check объединены в один OMP-параллельный цикл.

### 5. Сопутствующие изменения

- `AbstractGrid.h`: добавлен non-const `operator[](int idx)` (нужен для `Grid[l].UpdateState(corr)`)
- `AbstractCells.h`: добавлена перегрузка `UpdateState(const double* corrections)` (принимает массив в физическом порядке, без смещения в глобальный вектор)
- `CMakeLists.txt`: добавлен `CRSStructure.cpp` в GDM_CORE_SOURCES
- `ReservoirSimulator.cpp` строка 42: `Layout::InterleavedSwP` передаётся при конструировании

## Что НЕ изменено

- `fillMatrixBlockRow` — физический порядок `[d(oil)/d(Sw), d(oil)/d(P), d(water)/d(Sw), d(water)/d(P)]`
- `Wells.cpp` — контракт `rhsPerPerforation[l][0]=oil, [1]=water`, `matrixBlock[0..3]` в физическом порядке
- `AccountForBoundaryConditions` — физический порядок блока
- `Solve()` — `reinterpret_cast` rhs/corrections к `rhs_type<B>` работает для interleaved layouts
- `SparsityPattern.h/.cpp` — осиротевший класс, не используется, не удалён

## Архитектурные решения

1. **CRSStructure нешаблонный, Layout — runtime parameter конструктора.** Шаблонизация не нужна: Layout влияет только на построение CRS при конструировании, не на горячий путь (CopyBlock, AddDiagBlock).

2. **diagBlocks_ индексирован в физическом порядке.** Это ключевое решение — CopyBlock не нужно знать о Layout. Permutation "запечена" в diagBlocks при построении.

3. **Blocked layout — заглушка.** Для blocked layout строки CRS идут по переменным `(var, cell)`, а не `(cell, var)`. `reinterpret_cast` к `rhs_type<B>` создаст неправильные блоки — нужен скалярный backend AMGCL. Отложено.

4. **UpdateGrid объединяет update + convergence check.** Раньше был двухпроходный: (1) Grid.UpdateState для всех ячеек, (2) parallel for convergence check. Теперь однопроходный — каждая ячейка обновляется и проверяется в своём OMP-потоке. Безопасно: ячейки независимы.

## Нерешённые вопросы / следующие шаги

1. **CPR benchmark с Layout::InterleavedPSw** — основная цель сессии 6. Layout-абстракция — подготовительный этап.
2. **Удаление SparsityPattern** — класс осиротел, можно удалить при желании.
3. **Blocked layout** — требует скалярного backend AMGCL и другого подхода к Solve(). Для будущих задач.
4. **Performance regression?** — CRSStructure строится один раз при старте. Горячий путь (CopyBlock) не изменён. Регрессии не ожидается, но benchmark стоит прогнать.
