## Физическая модель

- Область: 500 x 500 x 40 м (4 пласта по hz = 10 м)

## Ключевые архитектурные решения

### Частичное вскрытие

Ядро GDM поддерживает произвольные интервалы перфорации через `SetOfPoints` (алгебра отрезков на прямой: sweep-line, union/difference). `WellJobTime(start, end, is_open, t)` описывает операцию над сегментом `[start, end]` в момент `t`. `TotalLength()` возвращает суммарную длину открытых интервалов.

`WellCompletionBuilder` должен поддерживать:
- `open_layer(k, t)` — открыть пласт k полностью `(0, hz)` в момент t
- `close_layer(k, t)` — закрыть пласт k полностью `(0, hz)` в момент t  
- `open_interval(k, start, end, t)` — частичное вскрытие `(start, end)` в пласте k
- `close_interval(k, start, end, t)` — частичное закрытие `(start, end)` в пласте k

Координаты — **локальные внутри пласта** (от 0 до hz).

### Разделение MER и перфораций

`WellScheduleBuilder` отвечает за дебит (MER-историю). `WellCompletionBuilder` — за состояние перфораций (ГТМ-историю). Это два независимых потока данных.

### Отложенный запуск скважины

Скважина, которая «появляется» в момент t > 0:
- MER-история начинается с shut-in (нулевой дебит) до момента t, затем рабочий режим
- Перфорации начинаются с момента t (до этого `WellJobsPerLayer[k]` пуст)
- `BringFirstPerforationToFirstMER()` выравнивает даты

## Критерии успеха

1. Сборка без ошибок
2. Все тесты проходят в Release
3. Баланс масс < 1e-3 относительная невязка
4. 0 ≤ S_w ≤ 1, P > 0 во всех 484 ячейках на каждом шаге
5. CSV-экспорт по слоям для визуальной верификации
