## Архитектура системы команд

Три набора команд с чётким разделением ответственности:

1. **`/issue`** — формирует контекст на GitHub: описание, анализ, предложения решения, имя ветки. Создаёт issue в репозитории.
2. **`/plan-*`** — создаёт детализированный план реализации в vault. Шаги, файлы, код, проверки, подводные камни. Готов к автономному исполнению.
3. **`/implement`** — реализует план: merge main→experimental → ветка → шаги → сборка → тесты → коммиты → vault → комментарий к issue.

Связь: `/issue` → GitHub issue → `/plan-*` → план в `vault/GDM/plans/` → `/implement` → код + vault → пользователь мёржит → experimental → dev → main

## Решения

- BUG и DEBT — один реестр (`известные баги и технический долг.md`), разделять при >30 записей
- Удалён старый `/plan` (единый) → заменён 5 специализированными командами
- Каждая plan-команда самодостаточна (без ссылок «аналогично /plan-fix»)
- Ветка по умолчанию: `experimental` (не `dev`, не `main`)
- `/implement` не закрывает issue — только комментирует «готово к merge»; закрытие при merge
- `/issue` не создаёт ветку — только предлагает имя и записывает в vault
- Warnings = ошибки (CLAUDE.md + implement): исправлять по существу, не подавлять pragma
- Тесты строго последовательно (без `-j` / `--parallel`)
